## 0. 怎么用这份清单

1. **一条一行勾**。每条都有「角色 / 入口 / 操作 / 预期」，按顺序做，预期不符就记下来（§11 给模板）。
2. **先做 §3 自检**。自检 5 条没过，后面的判定都不算数。
3 . **负面测试单独一节（§7 F）**。用错账号访问错接口，**必须被拒**——这一节挂掉是安全问题，不是"体验问题"。

5. 页面打不开时先看浏览器 F12 的 Network：接口返回 `{"code":401}` 是没登录/会话过期，`{"code":403}` 是角色不够。**HTTP 状态码永远 200**，业务码在 body 里，这是全站约定。

## 1. 让项目在你机器上跑起来（最短路径）

完整步骤见 `docs/给学校的部署说明.md`，这里是够用版。

### 1.1 环境

- JDK 17、Maven 3.9+、MySQL 8.0/9.x
- 不需要 Node.js（前端零构建产物已入库：`src/main/resources/static/`）

### 1.2 建库 + 建表（21 个脚本，按顺序）

```bash
mysql -u root -p -e "CREATE DATABASE nest DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

然后按 `docs/给学校的部署说明.md` §3 的 **21 个文件顺序**执行 `sql/` 下的脚本：

```
nest_schema.sql → nest_audit.sql → … → nest_loan.sql（第 21 个）
```

> ⚠️ `sql/` 目录里还留着**已下线教学模块**的旧脚本（`nest_course*.sql`、`nest_homework*.sql`、`nest_quiz*.sql` 之类），部署说明里没列到的**不要执行**。

### 1.3 改配置

把 `src/main/resources/application-example.properties` 复制成 `application.properties`（该文件已被 `.gitignore` 忽略，不会进仓库），至少改这三项：

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/nest?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8&allowPublicKeyRetrieval=true
spring.datasource.username=root
spring.datasource.password=<你的数据库密码>

app.upload.dir=<你的绝对路径>/uploads/avatars
app.upload.materials.dir=<你的绝对路径>/uploads/materials

nest.verify.pepper=<换成你自己的随机串>   # 出厂值时启动日志会 WARN
```

可选（不配也能跑，只是对应能力退化）：

```properties
# 大模型：不配 key，AI 辅助模块自动退回纯本地规则提取，功能仍可用
# 放在 config/local.properties（该文件已忽略）
nest.psyche.llm.api-key=sk-...

# 微信绑定：留空时接口会明确拒绝并说明原因，不会假成功
nest.wechat.appid=
nest.wechat.secret=
```

### 1.4 灌演示数据（**必做**，否则大量页面是空表）

```bash
# 先准备 MySQL 凭据文件（Windows），格式：
#   [client]
#   user=root
#   password=你的密码
# 然后：
powershell -ExecutionPolicy Bypass -File tools/demo-seed.ps1 -MyCnf C:\path\to\my.cnf
```

脚本三步：清测试残留 → 按依赖顺序跑 12 个 `sql/nest_*_demo.sql`（每个幂等）→ 跑 `tools/verify-demo.sql` 打印各模块条数。

### 1.5 启动

```bash
mvn -B -ntp spring-boot:run
```

启动日志里出现 `Tomcat started on port 8080` 即可。浏览器打开 `http://localhost:8080/login.html`。

同理手机端：用 `http://<本机局域网IP>:8080/login.html`（手机连同一 WiFi）。健康检查：`http://localhost:8080/api/second-class/health` 应返回 `{"code":200,...}`。

## 4. A · 平台与账号（10 条）

### A01 首页
- 角色：未登录
- 入口：`http://localhost:8080/` 或 `index.html`
- 操作：浏览落地页，点「登录」「注册」
- 预期：两处跳转分别到 `login.html` / `register.html`；无横向滚动条

### A02 登录
- 角色：全部
- 入口：`login.html`
- 操作：先输错密码一次，再输 `admin` / `123456`
- 预期：错密码提示「用户名或密码错误」（**不会告诉你还剩几次尝试**）；正确后按角色跳转到 §2.1 的落点

### A03 连续失败锁定
- 角色：用一个**你可牺牲的**账号（建议先建一个学生号）
- 操作：连续输错 6 次
- 预期：第 6 次起即使密码正确也登录失败；`users.failed_login_count` 累加，`locked_until` 被写入。管理员可在 `admin-users.html` 点「解锁」清掉

> ⚠️ 别拿 `admin` 做这条，锁 15 分钟（`nest.security.lock-minutes=15`）。

### A04 注册（学生 / 教师两条路）
- 角色：未登录
- 入口：`register.html`
- 操作 A：填用户名、密码、确认密码、手机号，**邀请码留空** → 提交
- 预期 A：注册成 `student`，`users.role='student'`
- 操作 B：邀请码填 `TEACHER2024` → 提交
- 预期 B：注册成 `teacher`；`teacher_invitation_codes.usage_count` +1

> 校验：密码强度（大小写/数字/符号至少三类）、两次密码一致、用户名唯一、手机号格式。邀请码错误时**不应**注册成教师。

### A05 忘记密码（**有已知限制**）
- 角色：未登录
- 入口：`login.html` →「Forgot password?」→ `forgot-password.html`
- 操作：填手机号 → 点「Get Code」→ 去服务器日志找 `[NEST-VERIFY]` 那一行拿 6 位码 → 进 `reset-password.html` 填码 + 新密码 → 提交
- 预期：接口返回 `delivered:false` + 中文说明（未接网关）；日志形如
  `[NEST-VERIFY] channel=log scene=reset_password target=13800000000 code=641360 expires_in=300s`
  ；用该码重置成功后可用新密码登录
- 限制：验证码**不会**真的发到手机（§10 L2）

### A06 登出
- 操作：右上角头像菜单 →「退出登录」
- 预期：回 `login.html`；再访问需登录的页面会跳回登录页

### A07 个人档案（学生改自己能改的）
- 角色：`wangxm`
- 入口：`profile.html`
- 操作：改「Self service · 我可以修改的」里的联系方式 → 保存
- 预期：保存成功；页头「我的假条」区块能列出该生请假记录；**只读字段（学号/班级/专业/辅导员）不可改**，改了也不生效

### A08 账号设置（四张卡）
- 角色：`wangxm`
- 入口：`settings.html`
- 操作：①「Basic Account Information」看用户名/角色/绑定状态 ②「Personal Profile」改昵称 ③「Change Password」改密码 ④「Third-party Binding」点微信绑定 ⑤ 改手机号（点「Send Code」→ 日志取码 → 「Update Phone」）
- 预期：③ 旧密码错时拒绝；④ 明确提示「未接入微信开放平台」并拒绝写库（**不会假成功**）；⑤ 与 A05 同样的日志取码路径

### A09 公告
- 角色：`wangxm` 看；`zhangsan` 发
- 入口：`dashboard.html`「学院公告」区块；发布入口在 `teacher-dashboard.html`「发布学院公告」
- 操作：教师发一条公告 → 学生刷新工作台
- 预期：学生能看到新公告；教师可编辑/删除自己的公告

### A10 双主题 + 手机端
- 操作：页头点 `dark_mode` / `light_mode` 切换；再把浏览器宽度拉到 375px
- 预期：两套主题文字对比度都正常（浅色 `nestlight` / 深色 `nestdark` 是两套 CSS 变量）；375px 下**无横向滚动**、按钮可点、**下拉框文字不被裁切**

## 5. B · 宿舍智能分配 + AI 辅助（核心，16 条）

> 这是大创的主线，建议**整节都测完**再测别的。
> 页面都是**管理员面**，必须用 `admin` 登录；教师账号进不去（`admin-dashboard.html` 会把 teacher 弹回 `teacher-dashboard.html`）。

### 5.0 入口说明（重要）

| 页面 | 怎么进 |
|---|---|
| `dorm-admin.html` 宿舍分配工作台 | `admin` 登录 → `admin-dashboard.html` → 右上「快捷操作」里 **NEST 宿舍分配** 按钮 |
| `dorm-psyche.html` 心理特征提取工作台 | 同上，**心理特征（NEST）** 按钮 |
| `dorm-portal.html` 学生自助端 | `wangxm` 登录 → `dashboard.html` → 右上「我的宿舍」或卡片 |
| `dorm.html` 功能自测台 | **没有任何页面链到它**，要手输 `http://localhost:8080/dorm.html`（§10 L9） |

### B01 一键分配（先跑一次基线）
- 角色：`admin`
- 入口：`dorm-admin.html` →「一键分配」标签
- 操作：参数保持默认（时间预算 30000ms / 种子 20260927 / 局部搜索轮数 12 / 阻塞对修复 开 / 预生成解释 开）→ 点「开始分配」
- 预期：8 张指标卡出现数字，**硬约束违规 = 0**、**未分配 = 0**；「历史批次」表格新增一行，可点「设为当前」。**这一步是一步到位同步返回，没有进度条**（设计如此，1000 人几十毫秒）

### B02 八张指标卡 + 诊断信息
- 入口：同 B01 结果区
- 操作：展开折叠的「诊断信息」
- 预期：指标卡 8 项齐全（硬约束违规 / 未分配 / 均值相容度 / 最差对 / 房内方差 / 志愿满足率 / 阻塞对数 / 运行耗时）；诊断里能看到 `blockCount`、`localSearchAcceptedMoves`、`blockingRepairsApplied` 三个数——这是"算法真跑了"的证据

### B03 消融对照（**怎么"看见"算法在动**）
- 操作：同一批数据改参数再跑，对比指标
  1. 局部搜索轮数 `12 → 0`：均值相容度应下降、最差对应变差、房内方差应变大
  2. 阻塞对修复 `开 → 关`：阻塞对数应从 0 变成正数
  3. 时间预算 `30000 → 500`：耗时下降，指标可能略差
- 预期：三个方向的变化都符合上面描述
- 注意：第 1 组的框叫「志愿簇预分组」，但**实际行为是把木桶项 + 志愿项权重归零**（`dorm-admin.html:277`），标签名不副实（§10 L8），演示时别照标签讲

### B04 数据准备：生成合成数据
- 入口：「数据准备」标签
- 操作：学生数 1000 / 种子 20260927 / 噪声 0.2 / 缺失 0 / 志愿紧张 0.5 / 楼栋 3 / 容量 4 → 点「生成并覆盖现有数据」
- 预期：`dorm_student` = 1000，`dorm_ground_truth` = 1000；**指标基准显示"真值"**（合成数据带隐真值，这是能算 MAE 的前提）
- ⚠️ 演示**必须**走这条路。手工导入的真实名单没有隐真值，指标会弹黄色警告说基准变成「模型预测值」（§10 L7）

### B05 数据准备：手工导入
- 操作：「导入」贴一段 JSON（11 维 feature 顺序：入睡/起床/吸烟/卫生/外向/在房间学习/噪声容忍/社交/物品共享/游戏/学业拼搏；**缺失写 `null`，不要写 0**）
- 预期：导入成功并提示基准已切换；写 `null` 的维度走均值插补，不是当成 0 参加计算

### B06 数据准备：清空
- 操作：点「清空宿舍域全部数据」
- 预期：宿舍相关表清空、批次列表变空。**注意这会删掉 §2.3 那 1000 行演示数据**，测完记得重跑 B04

### B07 房间视图
- 入口：「房间视图」标签
- 操作：按楼栋/房间筛选；点某个房间看成员
- 预期：房号、楼栋、入住人数、成员列表正确；259 间房能翻到

### B08 四维解释（**核心卖点，逐层看**）
- 入口：「四维解释」标签
- 操作：选一个学生 → 点「查他的解释」
- 预期：四层都有内容
  1. **相容度层**：逐维 contribution（哪些维度加了分、哪些减了分）
  2. **约束层**：命中了哪些硬约束
  3. **志愿层**：他和谁在志愿里互相点名
  4. **对比层**：「换一种分法会差多少」
- 另看来源标记：PRECOMPUTED（分配时预生成）或现场计算

### B09 申诉处理（三级）
- 入口：「申诉处理」标签
- 操作：看已有 5 条申诉 → 对一条点「采纳」；再试「跨块试算」
- 预期：状态取值 `SATISFIED` / `UNSATISFIABLE` / `NOT_FOUND_IN_SCOPE` 三选一；**采纳只改相关房间，不重跑全局**；跨块试算耗时明显更长（几十秒级），结果异步返回

### B10 公平性审计
- 入口：「公平性审计」标签
- 操作：选当前批次 → 点「看当前批次的公平性」
- 预期：按「专业大类 × 年级」分组给出满意度极差；分组数合理、极差是百分比

### B11 补采建议（MAA）
- 入口：「补采建议」标签
- 操作：看证据覆盖率、可评估率、零证据同房对、缺答格子；再取「催填优先级 Top-K」
- 预期：四个数字都有意义（缺失 0 时零证据同房对应为 0）；Top-K 列表按期望增益排序，点进去能定位到具体学生

### B12 原始响应
- 入口：「原始响应」标签
- 操作：跑一次分配后看这里

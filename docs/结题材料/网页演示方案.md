# 网页演示方案（给老师看的两块核心：AI 辅助分配 + 宿舍分配算法）

> 这份是**网页版**演示方案，和 `演示脚本.md`（命令行版，答辩现场用 `tools/pilot/demo.ps1`）互为补充：
> 命令行版跑的是「体检→导入→分配→审计→解释→申诉→学生端」的算法闭环，**不含 AI 那一路**。
> 本文补上「AI 辅助分配」的演示，并把两块串成一条老师可以在浏览器里点完的主线。
>
> 对应页面：`dorm-psyche.html`（心理特征提取工作台，AI 那一路）与 `dorm-admin.html`（宿舍分配工作台）。

---

## 0. 演示前准备（答辩前一天先走一遍）

1. **起环境**：应用起在 8080（或试点库 8081，见 `演示脚本.md` §0）。浏览器开两个页签：
   - `http://127.0.0.1:8080/dorm-psyche.html`（AI 那一路）
   - `http://127.0.0.1:8080/dorm-admin.html`（分配算法）
2. **登录**：管理员账号 `admin / 123456`。
3. **AI key 决策（演示前必须定好，见 §5 诚实边界）**：
   - 若现场能联网且配了 `nest.psyche.llm.api-key`：两块都能现场跑，最有说服力。
   - 若内网离线、没配 key：`llmReady()=false`，整模块自动退化为**纯本地规则提取**——不崩，但「大模型」那一档现场点不动。
     这时演示 AI 部分改用**提取器评测页的历史记录**（提前跑好留档）+ 讲清楚退化为规则的原因。

## 1. 演示主线（一句话）

> 先让 AI 把「学生自己说的话」变成「性格数字」，再让求解器拿这些数字去排宿舍，
> 最后用「四维解释 + 三级申诉 + 公平性审计」证明这间宿舍为什么这么分、分得公不公平。

顺序建议：**AI 提取特征（dorm-psyche）→ 分配算法（dorm-admin）**。
理由是老师一听「AI 辅助分配」会先问「AI 到底怎么帮上忙的」，先把这一环讲透，再落到「分配」。

## 2. 第一幕：AI 辅助分配（`dorm-psyche.html`）

### 2.1 先点「大模型自检」（页面右上角 `network_check` 按钮）

看什么：`/api/dorm/psyche/probe` 的返回。

- 配了 key 且连通 → 显示「就绪」，下面一路顺畅。
- 没配 key → 返回明确理由：「未配置 API Key。在 config/local.properties 里设置 nest.psyche.llm.api-key 后重启应用」。

**讲什么**：这一步是系统的「诚实自检」，AI 能不能用，现场先自己说清楚，不装。

### 2.2 「维度与题库」页（tab 4）—— 先讲清「AI 提取的是什么」

看什么：三块卡片。

1. **模块状态**：大模型就绪/未就绪、模型名、接口地址、并发上限、默认提取器、置信度阈值（默认 0.35）。
2. **提取流程（管线 6 步）**：
   ①收集素材（自述 / 聊天 / 辅导员观察 + 量表，需授权）→ ②特征提取（规则 + 大模型双路并行）→
   ③融合（量表优先；两路都有值时取高，接近取均值）→ ④落快照（附逐维证据）→
   ⑤采用（过置信度阈值才写回）→ ⑥分配（求解器读特征表，缺失维均值插补）。
3. **11 维特征口径**：作息（入睡/起床，小时，跨零点 +24）、卫生、吸烟、外向、在房间学习、
   噪声容忍、社交、物品共享、游戏、学业拼搏等，量纲 `0..1` 或小时。
4. **问卷题库**：题目代码、维度、类型、题干、选项。

**讲什么（这是 AI 部分的定性）**：

> 「AI 不直接分宿舍。AI 只做一件事——把学生自己写的一段话、一段聊天，翻译成 11 个
> 可比对的数字。这些数字喂给后面那个可解释的求解器，求解器才负责排房间。
> 所以『AI 辅助』的『辅助』，辅助在『把人变成数字』这一步，不在『拍板』那一步。」

### 2.3 「学生与素材」+「提取与采用」页 —— 现场走一遍四步

在「学生与素材」页选一名学生（点「选定」），跳到「提取与采用」页，按四张卡片走：

1. **① 录入素材**：贴一段学生自述（或聊天/辅导员观察），勾「是否授权提取」。
   - 讲：**授权开关是隐私底线**；授权=0 的素材不参与任何提取。
   - 讲：主语是「室友/同学/别人」的句子会被规则那一路自动排除（不把别人的习惯算到本人头上）。
2. **② 代录问卷作答**：作息题填小时原生值，其余 0..1。
   - 讲：**问卷权重高于文本推断**——那是学生自己明确说的，不能拿 AI 的猜去压过本人表态。
3. **③ 运行提取**：提取器选「融合规则+大模型」或「仅本地规则」。
   - 看返回：提取器名、请求人数、走大模型几人、纯规则几人、耗时。
   - 讲：**双路并行**——规则负责「确定的事」，大模型负责「从话里读出来的事」，两路取高、接近取均值。
4. **④ 采用到特征表**：按置信度阈值逐维筛选。
   - 讲（三条纪律）：**没有证据不给值**（留空走均值插补，绝不拿 0 顶）、**低置信度不采用**、
     **提取≠生效**（先落快照，采用才真正写回 `dorm_student_feature`，求解器只认这张表）。
   - 看返回：已采用 N 维、来源标记 `AGENT_LLM` 或 `RULE`、阈值、具体哪些维度被采用。

### 2.4 「提取器评测」页（tab 3）—— 回应「你怎么知道 AI 提得准」★

这是 AI 部分最有说服力的一页，务必讲。

- **做法**（页面里写得很清楚）：先给每个虚拟学生抽一份**真特征**，再把真特征**反写成一段学生口吻的
  自述与聊天记录**，然后**只把文字喂给提取器**，最后拿提取结果与真特征比。
  提取器全程看不到答案 → 量的是**真实的语义理解误差**，不是抄写误差。
- **两档按钮**：
  - 「只跑规则（约 1 秒）」—— 本地规则基线。
  - 「带大模型跑（按人头计费，约 1 分钟）」—— 每个人采样 2 次（温度 0 与 0.35），
    两次的差就是「不确定性估计」：分歧太大就把置信度压下去，最终被阈值挡掉。
- **看什么**：MAE（作息/其余）、|Pearson|、|Spearman|、收敛比、覆盖；以及「消融」表
  （剔除他人与助手发言，误差变化几个点）。

**讲什么**：

> 「评测和分配用的是**同一份会反写文字的合成数据**，不碰任何真实学生信息。
> 大模型采样两次、看它自己跟自己分歧大不大，分歧大就压低置信度——这就是
> 『不确定感知』：AI 不确定的时候，宁可少采用、也别硬猜。」

## 3. 第二幕：宿舍分配算法（`dorm-admin.html`）

### 3.1 「数据准备」页 —— 合成数据带「隐真值」

- 点「生成并覆盖现有数据」（默认 1000 学生 / 种子 20260927 / 噪声 0.2 / 楼栋 3 / 容量 4 / 年级混合）。
- **讲什么（这是算法可信的根基）**：

> 「生成器先抽真实特征 z，再定义一个**算法永远看不到**的真值相容度 g（含隐变量磁场项和
> 『早起×晚睡』交互项）。分配算法只看观测值，但所有指标都算在它看不到的 g 上。
> 这样『分得好不好』就有了标准答案，不是我们自己说好就好。」

### 3.2 「一键分配」页 —— 看指标卡 ★

参数：批次名、时间预算（默认 30000ms）、种子、志愿簇预分组（开）、阻塞对修复（开）、局部搜索轮数 12、预生成解释（开）。

点「开始分配」，看指标卡（要讲的就是这 8 个数）：

| 指标 | 应看到 | 讲什么 |
|---|---|---|
| 硬约束违规 | **0 ✓** | 必须恒为 0（性别不混住、同年级、容量不超、床位够） |
| 未分配人数 | 0 | 每个人都要有床位 |
| 均值相容度 | 正数（如 0.091） | 指标基准是「隐真值」还是「模型预测值」，页面上会标 |
| 最差那一对 | 接近 0 的正数 | 木桶效应：不看均值看最短板 |
| 房内方差 | 越小越均匀 | 房间内部和谐度 |
| 志愿满足率 | 百分数 | 楼栋/楼层志愿命中 |
| 阻塞对数 | **0** | 近稳定：没有「互相更想跟对方住、却没分到一起」的阻塞对 |
| 运行耗时 | 十几毫秒 | 拆三段：贪心 + 局部搜索 + 阻塞对修复 |

再看诊断区：`blockCount`（块数）、`localSearchAcceptedMoves`（局部搜索接受移动次数）、
`blockingRepairsApplied`（阻塞对修复次数）、`greedyMsTotal` / `localSearchMsTotal`（各阶段耗时）。

**讲什么（把「快」讲透）**：

> 「流程是——先按『性别 × 楼栋类型 × 专业大类 × 年级』切块（并行），块内
> 志愿簇预分组 → 最难的人优先贪心构造 → 局部搜索（含木桶守卫）→ 阻塞对修复 → 全局违规复核。
> 上万人的规模，靠**分块并行**才跑得动；块内再用局部搜索把软目标往上顶。
> 我们追求的是**容量约束下的『近稳定』**：不吹『绝对稳定』，因为零阻塞对是 NP-hard，
> 我们做到的是把阻塞对压到 0（小规模）并量化 gap。」

### 3.3 「四维解释」页 —— 一个学生为什么住这间房 ★

选一名学生，点「查询」。四层：

1. **叙述层**：人话版「你被分到 X 号楼-X，本房间平均相容度 …，最需要留意的一对是 …」。
2. **约束层**：哪条硬约束在这里生效（性别与楼栋匹配、年级不混住、房间容量）。
3. **特征层（逐维贡献）**：和谁、哪一维、差异多大、冲突明显/一般/未知。
4. **志愿层 + 对比层**：「换一种分法差多少」。

**讲什么**：

> 「解释不是事后编的，是分配时**预生成**好、随批次落库的（`来源：PRECOMPUTED`）。
> 老师或学生问『凭什么』，系统能逐条回答——甚至回答『这一项你们有人没填，不计入相容度』，
> 而不是拿 0 或均值硬顶。这是我们把『没回答』和『很合得来』区分开的一处关键修正。」

### 3.4 「公平性审计」页 —— 有没有哪类人系统性吃亏

按「专业大类 × 年级」拆组，看各组满意度极差。

**讲什么**：两个年级差多少、四个大类最大差多少——这就是主实验里「不显著的公平差距」在单个批次上的样子。

### 3.5 「补采建议」页 —— 「不确定感知」的另一半

看：证据覆盖率 Cov、可评估率、零证据同房对、缺答格子；催填优先级 Top-K（期望增益）。

**讲什么**：

> 「数据没填的维度，我们不猜。系统会告诉你『这 N 对同房的学生互相没证据，评估不了』，
> 并按期望增益排出『最该催谁先填问卷』——这就是『不确定感知』的工程落地：缺数据就明说缺，
> 而不是硬塞一个数进去。」

### 3.6 「申诉处理」页 —— 学生不服怎么办 ★★

三级申诉（页面里「采纳」=房间级重解，「跨块试算」=跨块级）：

- **房间级**：毫秒级，只动目标房间内部（跟谁对调）。
- **块级**：本块重解，秒级。
- **跨块级**：合并块 + 放宽政策，几十秒；状态 `SATISFIED / UNSATISFIABLE / NOT_FOUND_IN_SCOPE`。

**讲什么（两句话，比任何指标都打动人）**：

> 「学生说『我想跟某某住』，系统不会只说『不行』，它会算**满足你要动多少人、牺牲多少目标值**。
> 拒绝的时候，它把**放宽了哪一条政策**点名列出——这样管理员才知道，这个『不可能』是真排不出来，
> 还是系统没想到别的政策可以放宽。」
>
> 「三级申诉的成本要按**波及人数**说，不能只看目标值：房间级动 1 个人、跨块级动 13 个人，
> 目标变化可能是同一个数，但代价完全不一样。」

（完整的三级申诉样例、代价数字、用例 A/B，见 `演示脚本.md` §[11]。）

## 5. 诚实边界（主动说，比被问有利）

1. **AI 那一档要联网 + 配 key**：`nest.psyche.llm.enabled=true`、`base-url=https://api.deepseek.com`、
   `model=deepseek-chat`，`apiKey` 默认空 → `llmReady()=enabled && apiKey 非空`。
   内网离线时整模块退化为纯规则提取，不崩，但「大模型」档用不了。
2. **真实数据 = 0**：演示用的是合成数据（含隐真值）；真实数据没有隐真值，相容度指标只能是
   「模型预测值」，不能和合成数据的真值指标并排比。导入接口返回的 `note` 会主动声明这一点——建议念出来。
3. **评测也用合成数据**：提取器评测全程不涉及真实学生信息。
4. **阻塞对 = 0 是小规模结论**：零阻塞对是 NP-hard，我们用量化 gap 而不是宣称「绝对稳定」。

## 6. 现场出问题先看

- AI 档点不动 → 大概率是没配 key（先点「大模型自检」看理由）。
- 分配指标卡出现黄色告警 `metricBasisWarning` → 那是系统自我声明「这轮数据没有隐真值，指标是模型预测值」，
  **不是错误**，主动念出来反而是加分项。
- 其他环境/脚本坑（cookie 手工抓、`status:UP` 不是 `ok`、snake_case 字段、结构化建议项不能直接插值）→ 见 `演示脚本.md` §2。

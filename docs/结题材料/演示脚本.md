# 演示脚本（答辩现场用）

一条命令跑完 **体检 → 导入 → 分配 → 公平性审计 → 四层解释 → 三级申诉 → 学生端**。
本文是这份脚本的运行手册：先讲怎么起环境，再讲每一步「应该看到什么、为什么值得看」，
最后是踩过的坑（现场出问题时先看这一节）。

对应脚本：`tools/pilot/demo.ps1`（约 250 行）与 `tools/pilot/appeal-verify.mjs`。

---

## 0. 起环境（答辩前一天先跑通一次）

需要三样东西：**JDK 17**、**MySQL**、以及一份**试点库**。

### 0.1 准备试点库 `nest_pilot`

试点库和主库 `nest` 分开，演示怎么折腾都不会污染主库。建库办法是把 `sql/` 下的脚本
按顺序导入，但把脚本里写死的库名从 `nest` 换成 `nest_pilot`（脚本里共 5 处：
`USE nest;`、`CREATE DATABASE IF NOT EXISTS nest`，以及 `nest_psyche_v2.sql`
里 3 处 `TABLE_SCHEMA = 'nest'`）。顺序：

```
nest_init.sql → nest_seed.sql → nest_dorm.sql
→ nest_psyche.sql → nest_psyche_v2.sql → nest_appeal_v3.sql
```

导入完成后 `nest_pilot` 应有 **28 张表**。

> **为什么要单独一个库**：演示会真的执行 `replaceAll=true` 的整库替换导入。
> 用主库演示等于把实验结果和演示混在一起。

### 0.2 生成试点名单

```bash
node tools/pilot/build-pilot.mjs gen          # 生成 CSV 模板 + 324 人模拟名单
node tools/pilot/build-pilot.mjs convert      # 转成 target/pilot-import.json
```

`gen` 产出三份 CSV（名单模板 / 试点名单 / 试点房间），**带 UTF-8 BOM**，
用 Excel 打开中文不乱码。名单是 324 人 / 84 间房 / 324 床位，**每个普通块恰好住满 20 人**——
这一点很重要：只有恰好住满，CP-SAT 裁判才证得出最优。


## 1. 每一步应该看到什么

### [1] 环境自检
`HTTP 200；模块 dorm；状态 UP；服务自述 18 条路由`。接口不通就到此为止，别往下走。

### [2] 管理员登录
拿到 `JSESSIONID`（32 位十六进制）。**cookie 是手工从响应头抓的，不用 cookie jar**——
同一个 jar 上先后 `-c` / `-b` 会被下一次请求覆盖，实测会拿到 401。

### [3] 数据概况
`学生 324 / 房间 84 / 床位 324 / 志愿 151 / 带特征 106 / 批次 0`。

### [4] 体检（一）：故意给一份「什么错都有」的名单 ★
**这是全场最有说服力的一步。** 6 行学生的垃圾名单，系统当场逐条点名：

```
体检结论 ok=False；ERROR 5 条 / WARN 3 条
 · [ERROR] （students）学号重复。导入是按学号 upsert 的，重复学号会让后面的行
           覆盖前面的行，等于悄悄少了一个人（共 1 处，例如：第 1 行与第 2 行都是 BAD001）
 · [ERROR] （students）性别无法识别，只支持 M/F 或 MALE/FEMALE（共 1 处，例如：第 3 行 BAD003 写的是 "X"）
 · [ERROR] （students）特殊需求无法识别，可选 NONE / WHEELCHAIR / LOW_FLOOR / QUIET（共 1 处…）
 · [ERROR] （容量）床位总数 4 个，少于学生 6 人，差 2 个。硬约束要求每个人都有床位，
           导进去也无法完成分配。
 · [ERROR] （容量/F）「女生」学生 5 人，但同性别床位只有 4 个，差 1 个。
           男女不混住是硬约束，不可能靠调换房间化解。
 · [WARN] （students）年级为空。分块是按年级切的，缺年级的人会和所有缺年级的人归到同一块…
 · [WARN] （students）feature 第 0 位是入睡时刻，取值范围 20~26 小时…这里出现了越界值
 · [WARN] （志愿）楼栋志愿指向本次导入里不存在的楼栋，这条志愿会被忽略
```

要说清两件事：
1. **体检是只读的**，这一步没有写入任何数据，可以反复试；
2. 同类问题**合并计数并最多举 3 个例子**——一千行都缺年级时，要看的是
   「共 N 处，例如第 3、7、19 行」，不是一千行日志。

### [5] 体检（二）：真实形态的 324 人名单
`ok=True；ERROR 0 条 / WARN 0 条；学生 324 人；带特征 106 人`。
一个通过体检的名单长什么样，和上一步是同一双眼睛看出来的。

### [6] 导入
导入返回里带一句 `note`，是系统主动声明自己的边界：

> 真实数据没有隐真值，分配的相容度指标会是「模型预测值」，只能用于自检和展示，
> 不能拿去和合成数据实验的真值指标并排比较。

这句话建议在答辩时**主动念出来**——它比等着评委问「你怎么知道分得好」要有利得多。

### [7] 分配 ★
```
批次 id = 7（结题演示）
nest-block-greedy-ls-repair-v1 | 14 ms | 违规=0 未分配=0 阻塞对=0 | 软目标=-32.44 | 块=18(最大 20)
块 18 个（最大 20 人）；块内求解：贪心 11 ms + 局部搜索 65 ms + 阻塞对修复 2 ms；接受移动 28 次
指标：平均相容度 0.0912（模型预测值）/ 最差 -0.0080 / 房内方差 0.00701 / 志愿满足 36.0% / 公平差距（专业）0.0683
⚠ 当前数据没有隐真值，相容度指标为模型预测值，不可作为实验结论。
```

要讲的点：**324 人 / 84 间房 14 毫秒**，零硬约束违规、零未分配、零阻塞对；
并且把耗时拆到三个阶段（贪心 / 局部搜索 / 阻塞对修复），而不是含糊的「很快」。

> ⚠ 那一行是系统的**自我告警**，不是错误：这轮数据里没有藏起来的标准答案，
> 所以相容度只能是模型自己的预测。实验章节里的真值指标来自合成数据，两者不能混着比。

### [8] 公平性审计
按组拆开的满足度，一眼能看出有没有哪一类人系统性吃亏：

```
 · satisfaction.byGrade           2024     （160 人） = 0.0979
 · satisfaction.byGrade           2023     （160 人） = 0.0845
 · satisfaction.byMajorCluster    经管类   （80 人）  = 0.1366
 · satisfaction.byMajorCluster    人文类   （80 人）  = 0.0899
 · satisfaction.byMajorCluster    信息类   （80 人）  = 0.0701
 · satisfaction.byMajorCluster    工科类   （80 人）  = 0.0683
```

两个年级差 0.0134，四个大类最大差 0.0683 —— 这就是主实验里那个
**不显著的公平差距**在单个批次上的样子。

### [9] 取分配结果
324 行，字段是 snake_case（`student_id / room_id / room_label / building_id /
is_appealed / student_no / name / gender / grade / major / major_cluster /
special_need / building_pref`）。**接口不返回 `blockKey`**，脚本按语义自己拼
`性别|N或S|专业大类|年级`。

### [10] 四层解释 ★
```
对象：吴可欣 住在 女生1号楼-101（女生1号楼）
本房间平均相容度 = 0.3344；最需要留意的一对 = 0.0312；可评估 6/6 对
叙述：
 你被分配到 女生1号楼-101。本房间平均相容度 0.33（满分 1，负分表示明显冲突），
 最需要留意的一对是 0.03。其中和你冲突最明显的是「作息」这一项（与 林奕辰，冲突明显（差异 3.00））。
约束层（哪条硬约束在这里起了作用）：
 · [生效] 性别与楼栋匹配 —— 你被分到 女生1号楼-101，该楼为女生楼
 · [生效] 年级不混住 —— 你的年级是 2023，同房间室友均为同年级
 · [未绑定] 房间容量 —— 该房间容量 4 人，当前 4 人
特征层（逐维贡献，只列最吃紧的 4 维）：
 · 作息      与 林奕辰：你 22.0 / 对方 25.0（差异 3.0）- 冲突明显
 · 物品共享  与 朱芷若：你 0.07 / 对方 0.61（差异 0.54）- 一般
 · 卫生      与 林奕辰：你 0.88 / 对方 0.37（差异 0.51）- 一般
 · 吸烟      与 朱芷若：你  / 对方 0.18（差异 ）- 未知（这一项你们至少有一方没填，不计入相容度）
```

四层是：**约束层 → 特征层 → 志愿层 → 对比层**。注意最后一行——有一方没填的维度
标成「未知」并且**不计入相容度**，而不是拿 0 或总体均值顶上。这是我们自己查出并修掉的
一处评估偏差（把「没回答」当成「很合得来」），详见 `docs/实验与验证.md` 第 2.4 节。

### [11] 三级申诉 ★★
脚本自动挑两对，把每一级的代价、波及人数、放宽项原样打出来。

**用例 A：同块内、不同房**（让 吴可欣 与 张雨轩 同住）

```
[房间级] status=SATISFIED  elapsed=0ms
       建议: 与 赵诗琪 对调
       代价 totalCostDelta=-0.360872  budget=0.5        ← 动 1 个人，7 毫秒
[跨块级] status=SATISFIED  elapsed=24ms
       本次要动 13 位同学（合并块共 20 人 / 5 间房），全实例软目标 -32.44 → -32.80
       放宽: []
       代价 objectiveDelta=-0.360872
       波及 移动 13 人，合并 20 人 / 5 间
```

**这里要讲的不是「代价变大了」，而是「代价没变、波浪变大了」**：两级的
目标函数变化是**同一个数**（−0.3609），但房间级只动 1 个人，跨块级动 13 个人。
所以三级申诉的成本要按**波及人数**说，不能只看目标值。

**用例 B：跨年级同大类**（让 吴可欣 与 2024 级的 王欣怡 同住）

```
[房间级] status=UNSATISFIABLE  elapsed=1ms
       message: 这条诉求在你的硬约束下不可能满足：王欣怡 与你年级不同（硬约束：年级不混住）
[跨块级] status=NOT_FOUND_IN_SCOPE  elapsed=39ms
       message: 重解后 王欣怡 仍然没有和你住到一起。即使放宽了「年级不混住」、
                在 40 人的合并块内重解，也排不出满足你诉求的方案——「在我搜过的范围里没找到」
                不等于「无解」，但这一级已经是本系统最大的搜索范围。
       放宽: [{"flag":"enforceGradeHomogeneous","label":"年级不混住",
               "why":"你和希望同住的同学不在同一个年级，而当前策略要求同一房间内年级一致。"}]
       代价: 本次试算没有产出可采纳的方案，因此不报代价、也不报波及人数。
```

三级是：**房间级（毫秒级、只动目标房间内部）→ 块级（本块重解）→ 跨块级（合并块 + 放宽政策）**。
最后一级必须是最后一招，而且**代价必须报给管理员看**。

这段值得停顿一下讲：拒绝的时候系统把「放宽了哪一条政策」点名列出，而不是含糊说一句
「即使放宽上述政策」——因为管理员的真正问题是「这个『不可能』是真的排不出来，
还是系统没想到还有别的政策可以放宽」。

### [12] 学生端
以学生账号登录 → 绑定学号 → 看自己的分配与志愿。`我的分块：F|N|信息类|2023`，
脚本还会把它渲染成人话：**`女生 · 普通宿舍 · 信息类 · 2023级`**。

### [13] 汇总
`target\demo\` 里是本次全部原始响应体。**用编辑器打开，不要用 `Invoke-RestMethod`**——
它会把 UTF-8 中文解码成乱码，而这次演示的价值有很大一部分就在那些中文理由里。

## 2. 现场出问题先看这一节

这些坑都是实际踩出来的，症状离原因都很远。

| 症状 | 真正的原因 | 怎么办 |
|---|---|---|
| 脚本报 `Unexpected token 'æ£€ç»“è®º'` 等一堆 ParserError | 脚本是**无 BOM 的 UTF-8**，而本机 shell 是 **Windows PowerShell 5.1**，按 ANSI 读中文注释 | 给 `.ps1` 补 UTF-8 BOM（`EF BB BF`）。**改完脚本要重新补**——编辑工具写出的是无 BOM UTF-8 |
| 登录返回 HTTP 500 `JSON parse error: Unexpected character ('u' ...)` | 用 `-d '{"username":...}'` 内联 JSON，PowerShell 转交参数给原生 exe 时**把双引号剥掉了** | JSON 体写进文件，用 `--data-binary "@文件"` |
| 后续每个请求都 401 | 上一条的连带结果：登录失败 → 没拿到 `JSESSIONID` | 先修登录 |
| 健康检查轮询 40 次都失败，但应用日志明明 `Started ... in 6.789 seconds` | 响应里是 `"status":"UP"`，脚本按 `'ok'` 匹配 | 匹配 `data.status -eq 'UP'` |
| 批次名叫 `????` | 用 `Set-Content -Encoding ascii` 写含中文的请求体 | 用 `[System.IO.File]::WriteAllText(路径, 内容, [System.Text.UTF8Encoding]::new($false))`（BOM 也不行，服务端会报 JSON parse error） |
| `mvn package` 报 `Unable to rename '...jar' to '...jar.original'` | 8081 上的实例还占着那个 jar | 先停监听进程再打包。**否则胖 jar 会被覆盖成瘦 jar**（约 5 MB），去掉 `target\*.jar.original` 重打 |
| 分配行字段全是 `undefined` | 接口返回的是 **snake_case**（`student_id`），不是 camelCase | 按 snake_case 取字段 |
| `[object Object]` | 建议项是结构化记录（`Swap`：`studentName / fromLabel / toLabel / otherName / delta / note`），不能直接插值打印 | 按字段拼人话 |
| 失败路径打出「目标 0.0000 → 0.0000」「移动 0 人」，看着像「改动为零」 | 失败路径上的数字位是**占位 0**，不是「代价为 0」 | 判定**一律以 `status` 为准**，只有 `SATISFIED` 才报代价 |

## 3. 为什么这些脚本用 Node / curl 而不是 PowerShell 原生 cmdlet

写在文件注释里了，这里再记一遍，因为下次改脚本很容易忘：

- **不用 `Invoke-RestMethod`**：它把 UTF-8 中文解码成乱码。演示的价值一大半在中文理由里
  （体检的错误说明、申诉的放宽原因），乱码就等于没法讲。
- **不用 `ConvertTo-Json` 生成请求体**（`build-pilot.mjs`）：它会把「只有一个元素的数组」
  序列化成标量，`"wantRoommateWith": "CS23011"` 而不是 `["CS23011"]`，服务端反序列化
  `List<String>` 直接失败——而且**只在恰好填了一个志愿时才出现**，极难排查。
  `JSON.stringify` 没有这个行为。
- **cookie 手工抓**：见上。

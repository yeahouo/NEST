# NEST 学工平台改造路线图

> 2026-10 立。触发：指导老师要求把系统从「学生管理系统 / 课堂管理系统」改造为 **学工平台**。
> 用户在本轮给出的三个口径（逐条照此执行，不再反复确认）：
> 1. **真做学工业务模块**——请假/离校、奖惩资助、综合素质测评、辅导员工作台；
> 2. **整体改名为学工平台**，弃用 CodeClass 品牌；
> 3. **彻底移除**原有教学模块（课程/作业/测验/签到/资料）。
>
> 本机**没有 git 仓库**；动手前的完整备份在 `target\backup-xuegong-pre\`（src + docs + tools + pom.xml，2,689 文件 / 39.4 MB）。
> 所有删除动作都必须能从这个备份还原。

## 一、改造后的定位

| | 改造前 | 改造后 |
|---|---|---|
| 面向 | 课堂教学（课程/作业/测验/签到） | **学生工作**（辅导员 + 学生 + 学工管理） |
| 品牌 | CodeClass LMS | **学工平台**（厦门大学嘉庚学院） |
| 核心资产 | 课堂管理 | **NEST 宿舍智能分配与可解释决策支持**（保留，作为学工子模块） |
| 保留模块 | — | 账号与权限、公告、宿舍分配、心理特征提取、审计日志、艺术/动效层 |

- 认证与权限：`AuthController`、`SecurityConfig`、登录锁定、密码策略（`PasswordPolicy`）、审计（`AuditLogService` / `AuditLogInterceptor`）；

**移除的教学模块**（迁移到 `target/backup-xuegong-pre/` 后从工作树删除）：

### 2.16 背景底纹加强（用户反馈，非阶段项）

**起因**：2026-10-16 用户三次反馈视觉，第一条「那个艺术效果有线会粘到我的鼠标指针上…就是这个线颜色太浅不明显」⇒ 粒子抓取连线调参；第二条「现在线条是明显了但是发出线条粘我鼠标的线条所在的背景那些几何条框不明显」⇒ 我按「页面底纹」理解做了三处底纹加强（见下，保留）；第三条用户澄清「我的意思是一些几何形状的东西会发出线黏住我的鼠标的那个效果…我想让那个几何形状的那些东西更明显」⇒ **用户指的从来不是底纹，是会发出抓取线的粒子点本身**，于是补做粒子点加强（见「粒子点（第四段）」）。教训一句：用户用「背景」形容前景装饰时，先问「你说的是哪个元素」比先改 CSS 便宜。

**D1 真漏洞（本轮修掉）：头像接口路径穿越**。`UserService.loadAvatarFile` 原为
`uploadPath.resolve(filename).normalize()`，`filename` 零校验，Windows 上 `\` 与 `/` 同为分隔符 ⇒
`..\..\application.properties` 可把含数据库口令的配置原样读出；且该接口**不要求登录**。
修法三层：①控制器要求会话，匿名 → 403 空体且不调服务；②服务层白名单
`^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` + 显式拒 `..`/null/空串 → 403（**不回默认头像**，避免把「拒绝」
误读成「没头像」）；③`normalize()` 后判 `startsWith(uploadPath)` 兜底。

**D2 修掉（本轮第二个真缺陷）：头像上传在未登录 / 非 multipart 时吐 HTTP 500**。
`POST /api/user/avatar` 原签名 `@RequestParam("file") MultipartFile file`，Spring 在**参数解析阶段**就要求
multipart，解析失败直接抛 `Current request is not a multipart request`，登录判断根本没跑到，异常被兜成
HTTP 500。改成 `@RequestParam(value = "file", required = false)` 后：匿名 → `code 400 未登录`，已登录但没带
文件 → `code 400 请选择要上传的文件`（服务层原有校验接管）。

**真机三身份矩阵（新增 `tools\authz-live.mjs`）**：静态读代码只能证明「控制器里有没有调守卫」，于是再补一层
真机实测——读 `target\authz-matrix.json`，用匿名 / 学生 chendw / 教师 lisi 三种身份打一遍，落后

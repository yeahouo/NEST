# 创新点：不确定感知的宿舍分配（Missingness-Aware Assignment, MAA）

> 本文件回答一个问题：**在把 B07（Fidan & Erdem 2021, Knowledge-Based SRTI）读懂之后，我们的宿舍分配到底哪一点不是「照搬论文」？**
> 结论先说：论文把「偏好表已知且完整」当前提，我们把这个前提拿掉——**问卷必然残缺，于是「问谁、信到什么程度」本身变成了待优化的问题**。
> 相关文档：`docs/宿舍分配算法-文献对照.md`（逐项对照表）、`docs/实验与验证.md`（既有实测）、`docs/学工平台改造路线图.md`（工程落地）。

---

## 1. 论文的前提，恰好是真实学校的破口

| | B07（SRTI 系列） | 本项目（NEST） |
|---|---|---|
| 输入 | 两人一间，每名学生一份**完整**偏好表（按准则的强弱序） | 4 人间分块，每名学生一份**可能残缺**的问卷（8 个用于打分的软特征 + 1 个不参与打分的ambition） |
| 残缺怎么处理 | 不在模型里：表不完整（ties / 缺项）只影响「可比的准则数」，不进入优化目标 | 主动处理：**未知维度的贡献是 0（中性）**，且「为什么是 0」有明确论证 |
| 目标 | 稳定性（无 blocking pair）是**硬保证** | 稳定性只作为**指标**（阻塞对计数），主体是加权相容度 + 志愿 + 公平 |
| 可解释 | 解释「为什么把 a 和 b 放一起」= 引准则 | 解释「这一对**有多确定**」= 逐维已知/未知 + 权重覆盖率 |

论文的完整度实验里，25% 缺项时理论有效完整度 81%、实测 83%——**它的缺项是「准则没填」，不是「观测没采到」**。而真实学生问卷的缺项是后者：某个学生**根本没答「你几点睡」**。这两件事在数学上完全不同：前者变成 ties，后者变成 *unknown*，而 unknown 不能被当成「两人生效差异为 0」——那是在断言一件谁都不知道的事（本项目早期就踩过这个坑，见 §2 H1）。

**所以创新点不是「我们也做了个性化权重」**（那是论文的 Personalized-SRTI，我们只当基线），而是：**把缺失当成一等公民，让分配器、解释器和问卷催填三件事围绕「信息不足」运转。**

## 2. 三条可证伪的命题

### H1　缺失语义：未知 = 中性，而不是「用均值补上」

对同房对 $(i,j)$ 与维度 $d$：

$$
c_{ij} = \sum_{d=1}^{8} w_d \cdot \tilde c_d(i,j), \qquad
\tilde c_d(i,j) = \begin{cases} c_d(i,j) & \text{双方第 } d \text{ 维都已知}\\ 0 & \text{任一方未知}\end{cases}
$$

其中 $w_d$ 为 `CompatWeights` 默认权重（作息 .20 / 吸烟 .20 / 卫生 .14 / 外向 .10 / 学习噪声 .14 / 游戏噪声 .10 / 社交 .06 / 共享 .06），$c_d \in [-1,1]$。

均值补齐（$\tilde c_d = c_d(\text{mean}_d, \cdot)$）会带来两个具体错误：

1. **制造假证据**：两个都没答「吸烟」的学生差异被算成 0.00，解释层显示「很合」；
2. **奖励少答题**：答得越少，越容易被算成与所有人相近 ⇒ 系统会倾向于把「没答题的人」配在一起，看起来分数还不错。

**已实现**（`RuleBasedCompatibility.java:24-33` 的类注释把理由写死，并刻意删掉了 `imputed(mean)` 那一行）。已有实测：缺失率 0% 时结果与旧版**逐位不变**；缺失率约 50% 时，NEST 相对 B2 的领先从 +1.46% 收窄到 +0.33%——我们把「模型预测值」与「隐真值」之间的差距**如实报出来，而不是靠补齐把差距藏掉**（`docs/实验与验证.md` §2.4）。

### H2　可评估性门限：告诉用户「这个方案有多少是算出来的、多少是占位」

定义一次分配 $S$ 的**证据覆盖率**：

$$
\mathrm{Cov}(S) = \frac{1}{|P(S)|}\sum_{(i,j)\in P(S)} \sum_{d:\ \text{both known}} w_d ,\qquad
\mathrm{Eval}(S) = \frac{\bigl|\{(i,j)\in P(S):\ \exists d\ \text{both known}\}\bigr|}{|P(S)|}
$$

- $\mathrm{Cov}$ = 这一对的相容度里，**有多少权重是真有数据支撑的**（0~1）；$\mathrm{Cov}=0.3$ 意味着「这一对 70% 的权重是中性占位，分数不可当真」。
- $\mathrm{Eval}$ = 有多少对**至少有一维可比**（严格意义上的「可评估对」）。

这条指标的用处不是好看，是**质量门限**：当 $\mathrm{Cov}(S)$ 低于某条线，系统应当**拒绝把分数当结论**，转而输出「需要补采哪些问卷」。论文里的「有效完整度」只用于解释实验结果，而我们把它抬成**面向用户的产出**（`已算 vs 待补`），并作为 §2 H3 的入口。

### H3　信息价值（VOI）：补问卷有预算，问谁最值钱

真实场景：开学前只能再催一轮，**最多补 10% 的问卷格子**。于是问题变成：给定缺失集合 $\mathcal{M}=\{(i,d): x_{id}=\text{unknown}\}$ 与预算 $k$，选哪 $k$ 个格子补齐，使分配结果的真值质量提升最大？

单格的期望增益（一次性、批量选择，不做序列贝叶斯更新）：

$$
\Delta_{i,d} = w_d \cdot \frac{1}{|\mathcal{C}(i)|}\sum_{j\in\mathcal{C}(i)} \mathbb{E}_{v\sim \mathcal{D}_d}\bigl[c_d(v, x_{jd})\bigr]\cdot \mathbb{1}[x_{jd}\ \text{known}]
$$

- $\mathcal{C}(i)$：与 $i$ 同性别、可能同房的候选人集合（分块后同块优先，退化为全体同性别）；
- $\mathcal{D}_d$：该维在学生群体上的经验分布（用数据里**已观测**的值估计；不引入外部先验）；
- 若对方该维也未知，则补了也仍是中性 ⇒ 增益 0（这符合直觉：两个人都没答的问题，补一个人的没有用）。

按 $\Delta_{i,d}$ 降序取前 $k$ 个格子 = **「优先催填名单」**。这与 SRTI 的任何机制都不重叠：论文假设表已经拿到，问谁是无意义的问题。

> **诚实边界**：实验里「补齐」的值取隐真值 $g_{id}$（等价于学生如实作答、且不含观测噪声），因此测出的是**收益上界**；若补齐值带噪声，收益只会更小。这一点会在实验报告里明写，不用来夸大效果。

## 3. 为什么这不是「工程包装」

评审最可能问三句，先自答：

1. **「不就是缺失值处理吗？」** —— 缺失值处理的常规做法是插补（把不知道变成猜一个数），我们做的是**反插补**：承认不知道、把「不知道」计入解释与决策，并用它来决定**下一个动作**（问谁）。插补是数据清洗动作，VOI 是决策动作。
2. **「和论文的差別只是目标函数不同？」** —— 目标函数不同是次要的；主要差别是**问题的定义域变了**：论文的优化变量是分配，我们的优化变量是「分配 + 信息采集」的联合，且后者有真实预算约束（一轮催填、10% 名额）。
3. **「有没有可能就是你说的那个『比论文更聪明』的自我吹捧？」** —— 所以三条命题都配了**可证伪的实验**（§4）：H1 有「均值补齐 vs 未知中性」的对照；H2 有「Cov 与真值误差的单调性」；H3 有「VOI 选 10% vs 随机选 10% vs 不补 vs 均值瞎补」的四臂对比。哪条打不出来，就从结题材料里撤掉。

## 4. 实验设计

统一口径：合成数据 + 隐真值（见 `docs/实验与验证.md` §1）；得分一律**在隐真值上评**（`BASIS_TRUTH`），模型侧只看得到问卷观测；同一配置多随机种子，配对比较。

| 实验 | 目的 | 自变量 | 因变量 |
|---|---|---|---|
| **E-A 可评估性** | H2：Cov 能不能当质量门限 | 缺失率 ∈ {0, 0.25, 0.50, 0.75} | Cov、Eval、零证据对数、\|模型分数 − 真值分数\| 的平均绝对误差（MAE） |
| **E-B 信息价值** | H3：VOI 选格子是否优于随机 | 补齐策略 ∈ {不补, 随机, VOI, 均值瞎补}，预算 = 缺失格子的 10%（另扫 30% / 60%） | 真值均值相容度、最差那对、房内方差、阻塞对、Cov、换室友人数 |

> 实际执行比预登记多做了两件事（都是**先加后跑**、不是为了凑结论）：① E-A 的缺失率加到 75%（原计划到 50%，但 50% 时 Cov 还有 0.20，不足以说明「门限该设在哪」）；② E-B 增加**预算扫描**（10% / 30% / 60%）与「换室友人数」指标，因为 10% 预算只在 n=60 上改了 33 格、真值指标打平——必须证明「不是 VOI 无效，而是这个预算下决策对该信息不敏感」。10% 仍是主结果。

E-B 的四臂定义（同一份缺失数据、同一套真值、同一求解器）：

| 臂 | 动作 |
|---|---|
| `none` | 什么都不补，直接分（现状） |
| `random` | 随机挑 10% 缺失格，用真值补齐 |
| `voi` | 按 §2-H3 的 $\Delta$ 取前 10%，用真值补齐 |
| `mean` | 按 VOI 挑同样 10% 格，但**填总体均值**（对照：假证据到底有没有用） |

预登记判据（跑之前写死，避免事后挑结论）：

- **P1**：`voi` 的真值均值相容度 > `none`，且 > `random`（配对、同种子、逐配对比）；
- **P2**：`mean` 不低于 `none` 才算「假证据无害」；若低于 `none`，则证明**插补会主动损害**分配质量（对 H1 是更强的证据）；
- **P3**：Cov 越低，\|模型分数−真值分数\| 的 MAE 越大（E-A，按缺失率分组看单调性）。

三条判据的结果（含「不成立/只部分成立」的处理）见 §7，**不因结果改写判据本身**。

## 5. 与论文的关系（能引什么、不能吹什么）

| B07 的成分 | 我们的处置 |
|---|---|
| SR / SRTI 的稳定性定义、Gale-Shapley 来源 | **引用**（我们把它作为对照指标的理论出处；`StabilityAudit` 的阻塞对是更严的变体） |
| Personalized-SRTI 的**每生准则权重** | 作为**基线**实现（可配置权重，`CompatWeights`），**不宣称创新** |
| Most-SRTI 的全体排序 + 分层弱约束 | 不实现（架构不同）；只引用其「准则优先级」思想 |
| Diversity（跨专业混住 / forbidden） | 作为**可选策略**吸收，**不宣称创新**（它在论文里已有） |
| ASP / CLINGO 求解 | 不采用（内网无外部求解器；我们用纯 Java + 可选 CP-SAT 裁判） |
| 论文的规模（n=200，求最优先稳定解 51.6–140.4 s；真实 81 人数据 4403 s） | 对照项：我们在 n=200 时 1.6–4.1 s 即可证明最优（CP-SAT 裁判），n=5000 时 218 ms |

**一句话边界**：稳定性、每生权重、跨专业混住都是论文的；**未知语义、可评估性门限、补采决策（VOI）** 是我们的。

## 7. 实测数字（2026-10 实测，10 个种子，可复现）

统一口径：n=200、4 人间、问卷噪声 0.20、缺失率 0.50（E-A 另扫）、隐真值评分、补齐值取 $g$（收益上界）。原始报告：`target/evaluability.md`（E-A）、`target/info-value.md`（E-B 主结果）、`target/info-value-sweep.md`（预算扫描）。

### 7.1 E-A：可评估性随缺失率单调崩塌（H2）

| 缺失率 | Cov | 可评估率 Eval | 零证据同房对（均值/总数） | MAE |
|---|---|---|---|---|
| 0.00 | 1.000 | 1.000 | 0 / 268 | 0.0985 |
| 0.25 | 0.481 | 0.997 | ≈1 / 267 | 0.3556 |
| 0.50 | 0.200 | 0.876 | ≈32 / 268 | 0.5105 |
| 0.75 | 0.056 | 0.407 | ≈159 / 268（**59%**） | 0.5979 |

读法：**缺失 25% 时九成以上的相容度权重仍是空的（Cov 0.481），而 75% 时六成的同房对「一维都不可比」却照样被打分、被解释。** 这正是 H2 要的门限：不是「分数不好看」，而是「分数没有证据」。建议门限 `Eval < 0.5` 或 `Cov < 0.15` 时拒绝把分数当结论，先输出补采清单。

### 7.2 E-B 主结果：10% 预算，四臂 × 10 种子（H3）

| 臂 | 均值相容（真值） | 最差那对 | 房内方差 | 阻塞对 | Cov | 可评估率 | MAE | 换室友人数 |
|---|---|---|---|---|---|---|---|---|
| `none` | 0.6475 | 0.1422 | 0.0126 | 346.7 | 0.200 | 0.876 | 0.5105 | — |
| `random` | 0.6457 | 0.1387 | 0.0128 | 345.9 | 0.243 | 0.928 | 0.4829 | 86.5 |
| `voi` | **0.6496** | **0.1179** | **0.0124** | **345.3** | 0.315 | 0.973 | 0.4365 | 116.9 |
| `mean`（同批格填均值） | 0.6474 | 0.1403 | 0.0128 | 344.5 | 0.320 | 0.974 | **0.4228** | 98.0 |

配对差（同种子逐对比，均值 ± 标准差，10 种子）：

| 对比 | Δ均值相容 | Δ最差那对 | Δ阻塞对 | 均值相容提升的种子数 |
|---|---|---|---|---|
| `voi − none` | **+0.0021 ± 0.0060** | −0.0243 ± 0.0709 | −1.4 ± 3.0 | **6/10** |
| `random − none` | −0.0018 ± 0.0053 | −0.0035 ± 0.0168 | −0.8 ± 2.1 | 5/10 |
| `voi − random` | **+0.0039 ± 0.0074** | −0.0208 ± 0.0697 | −0.6 ± 2.4 | **8/10** |
| `mean − none` | −0.0001 ± 0.0043 | −0.0019 ± 0.0878 | −2.2 ± 2.7 | 5/10 |

### 7.3 预算扫描：收益随预算单调放大，VOI 始终压住随机（H3 的剂量-反应）

| 预算（补齐格/缺失格） | `none` | `random` | `voi` | `mean` | voi − random |
|---|---|---|---|---|---|
| 10%（103/1029） | 0.6475 | 0.6457 | **0.6488** | 0.6477 | +0.0031 |
| 30%（309/1029） | 0.6475 | 0.6487 | **0.6540** | 0.6501 | +0.0053 |
| 60%（617/1029） | 0.6475 | 0.6569 | **0.6646** | 0.6529 | +0.0077 |

「最差那对」在三个预算上都是 `voi` 最好（0.1422 → 0.1202 / 0.1115 / 0.1148），`mean` 反而最差（0.1525 / 0.1483 / 0.1616）——**插补会把最差的一对掩盖成中等，真值补齐才会把它抬起来**。

> 注：§7.2 的 10% 行与 §7.3 的 10% 行来自**两次独立运行**（solve 用的是 `System.nanoTime` 截止的时间预算，见 §7.6③），故数值在第 3~4 位小数上差 0.001 量级；两份报告各自的内部对比（配对差、四臂相对大小）不受影响。

### 7.4 判据结论（照 §4 的预登记逐条判，不打补丁）

- **P1 成立**：`voi` > `none`（6/10 种子，+0.0021）且 > `random`（8/10 种子，+0.0039）。幅度小是真实情况：10% 预算只补 103/1029 格，**且 200 人里有 117 人的室友因此改变（59%）**——决策动了很多、质量只涨 0.2%，说明目标函数在这一点附近**很平**。所以本项目的结论是「VOI 在同等预算下更会挑格子」，**不是**「补 10% 就能提升分配质量」。
- **P2 判定为「无可测收益」而非「主动损害」**：`mean − none = −0.0001 ± 0.0043`，与 0 无法区分（5/10 种子为正）。但 `mean` 臂的 **MAE 最低（0.4228，比 `voi` 的 0.4365 还低）**，而决策质量并没有更好——**插补能把 MAE 刷低 0.09，却买不到任何决策价值**。这是一条方法学结论：只用「模型分数 vs 真值分数」的误差评价缺失处理，会被均值插补骗过去；必须看真值侧的分配结果。
- **P3 成立**：缺失率 0 → 0.25 → 0.50 → 0.75 上 MAE 单调上升（0.0985 → 0.3556 → 0.5105 → 0.5979），Cov 同步单调下降（1.000 → 0.481 → 0.200 → 0.056）。

### 7.6 必须写进「不足」的三条

1. **收益上界**：补齐值取隐真值 $g$（学生如实作答、无观测噪声），真实催填带噪声，收益只会更小；
2. **只做了 10 个种子、单一规模**（n=200、4 人间、分块硬约束），未做跨规模（n=1000+）与跨宿舍口径（两人一间）的稳健性；
3. **VOI 是一次性批量选择**，没有做序列更新（补一批→重算→再挑），因此不能声称「最优催填顺序」。

另有一条实现层面的如实交代：`NestSolver` 的局部搜索带**时间预算截止**（`System.nanoTime` 判定，`NestSolver.java:61`），所以同一配置两次运行的结果会在第 3~4 位小数上有小幅波动——本文件所有数字都取自 `target/*.md` 里那一次运行的输出，不做事后挑选。

## 8. 已经在系统里落地（不是只有文档和实验）

创新点如果只停在论文和实验脚本里，答辩时最容易被问「那你系统里做了吗」。所以 H1/H2/H3 已经做成宿舍管理端的一个只读功能：

| 层 | 位置 | 说明 |
|---|---|---|
| 算法（纯函数，无 DB） | `src/main/java/com/umi/nest/dorm/eval/MissingnessAdvisor.java` | 可评估性 `coverage(...)`、单题缺失统计 `cellTallies(...)`、信息价值排序 `rank(...)`；**不另写一套八维公式**，直接用 `RuleBasedCompatibility.explain(...).dimensions()` 取已加权分维贡献，保证与生产打分口径永不漂移 |
| 服务（只读） | `src/main/java/com/umi/nest/dorm/service/MissingnessService.java` | 取数 → 调算法 → 拼前端形状；**不读 `dorm_ground_truth`**，不看隐真值 |
| 接口 | `GET /api/dorm/missingness/summary?batchId=`、`GET /api/dorm/missingness/priority?limit=` | 走 `DormStaffInterceptor` 白名单，**默认只有 admin 能访问**；只读，不写任何表、不改分配结果 |
| 页面 | `src/main/resources/static/dorm-admin.html` 第 8 个 tab「补采建议」 | 上半是「这份分配能不能当结论」（Cov / 可评估率 / 零证据同房对 / 门禁徽标 + 两条理由），中间是「哪几道题最缺」，下半是「问卷催填优先级 Top-K」表（排名 / 学生 / 学号 / 建议补采 / 期望增益 / 已知对照人数），预算截断时页面上会标出来 |

**实测三条（2026-10-17，:8080 真实接口 + 真实数据 1000 名学生 / 1469 个同房对）**：

1. 全员答齐：`missingCells=0 / 10000`、`cov=1.0`、`evalRatio=1.0`、`evaluable=true`、`pairsWithoutEvidence=0`；
2. 把 333 名学生（三分之一）的吸烟 / 整洁 / 噪声三题置空：`missingCells=999`、`cov=0.6814`、`evalRatio=1.0`、仍 `evaluable=true`，催填表给出 999 个待补格子里的 Top-K（实测第 1 名 `S000738` → 噪声容忍，期望增益 0.2263，已知对照 26 人，共 84,048 次评估、未截断）；
3. 把 800 名学生（80%）的 11 题全部置空：`cov=0.0209`、`evalRatio=0.0395`、`pairsWithoutEvidence=1411/1469`、`evaluable=false`，两条理由原样返回——「证据覆盖率 0.021 低于门限 0.15：室友对大部分维度双方都没答过」「可评估对占比 3.9% 低于门限 50%：近半同房对一维都不可比」。**这就是 H2 想说的话：这时候的分数不能当结论。**

边界（页面上也写了）：`delta` 是**期望**增益，回答「先问谁、问哪题」，不承诺补了就一定涨名次；候选室友只在「同性同年级」里等距抽样，样本值取该校该题的经验分布（最多 4 个）；一次请求最多 25 万次相容度评估，超出即截断并显式标记。

测试：`MissingnessAdvisorTest`（9 个，纯算法，含「全员都缺这题 ⇒ 增益必须为 0、不编造收益」「评估次数超预算必须截断」）+ `MissingnessServiceTest`（7 个，钉批次回退、limit 钳制、无批次不报错、行形状）。

复现：

```bash
mvn.cmd -B -ntp "-Dtest=MissingnessAdvisorTest+MissingnessServiceTest" test
# 接口（先登录 admin，拿到 JSESSIONID）
curl -s -H "Cookie: JSESSIONID=$SID" "http://127.0.0.1:8080/api/dorm/missingness/summary"
curl -s -H "Cookie: JSESSIONID=$SID" "http://127.0.0.1:8080/api/dorm/missingness/priority?limit=20"
```

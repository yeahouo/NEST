## 1. 这套系统由什么组成

| 层 | 技术 | 说明 |
|---|---|---|
| 算法核心 | 纯 Java 17，零 Spring 依赖 | 包 `com.umi.nest.dorm`（model / config / compat / data / solver / eval / psyche / cli）。可脱离 Web 单独用命令行跑实验 |
| 后端服务 | Spring Boot 3.2.3 + MyBatis + MySQL | REST 接口，统一返回结构 `{code,message,data}` |
| 前端 | 静态 HTML + 预编译 Tailwind CSS + daisyUI 4 | **48 个页面**（2026-10-18 实测），全部响应式；PWA 学工化（2026-10-14）：27 个学生端页注册 Service Worker（实测 29/48 页引用 `/pwa.js`），可装到主屏、可离线（管理页不注册，见 §10 第 14 条） |
| 求解器 | 自研「块分解 + 贪心 + 局部搜索 + 阻塞对修复」 | 万级数据秒级出结果，硬约束违规数恒为 0 |

**多端说明**：后端是纯 REST，算法核心与 Web 层解耦，因此任何客户端都能接。
当前已交付 H5（响应式 + PWA，可添加到手机主屏）；微信小程序是同一套 API 的第二个壳，不需要重写后端。

### 学生到底要提交什么（宿舍分配模块）

> **范围说明**：本节只讲 **NEST 安居（宿舍分配）** 的数据输入。学工平台其余模块（请假离校、学生档案、奖惩、资助、综合素质测评、辅导员工作台、勤工助学、困难认定）的输入与流程见 `docs/课堂管理系统-功能补全说明.md` §25.3。

按「填得越少越有人填」的顺序分成四级，前两级是必须的，后两级愿意填就更好：

| 级别 | 内容 | 大约耗时 | 谁来收集 |
|---|---|---|---|
| 0 级 | 学号、姓名、性别、年级、专业、**特殊需求** | 学生不填 | 学校从教务 / 学工导入 |
| 1 级 | 想同住的室友（≤5 人）、明确不想同住的人（≤5 人）、楼栋意愿（≤3 个） | 约 10 秒 | 学生在「我的志愿」页签自己填 |
| 2 级 | 作息（几点睡、几点起）、现在是否吸烟、作息规律性 | 约 1 分钟 | 学生在「问卷与自述」页签填，选填 |
| 3 级 | 其余题目 + 一段自由描述 | 看学生愿意写多少 | 同上 |

第 1 级是**对分配结果影响最大的一个输入**（求解器的志愿项直接建在它上面），所以学生端专门做了一个「我的志愿」页签：填的时候会当场告诉学生每个志愿对象能不能和他住到一起、为什么不能，不必等分配结果出来才发现填了没用。第 3 级的自由描述信息密度最高——大模型能从一段话里抽出全部 11 个维度，覆盖率 96.6%，而规则法只有 78.4%。

**不填的学生不会被惩罚（有实验数据）**：当特征缺失率从 0% 升到 50% 时，本系统相对「按学号顺序」的现行做法，均值相容度优势从约 **+14%** 降到约 **+8%**，仍然显著为正。但这有个前提必须守住：**缺失必须记为「未知」，不能拿默认值顶替**。代码里缺失用 SQL NULL 存储、读出来还原成 `Double.NaN`（见 `DormRepository` 类注释），因为「没回答」和「打 0 分」是两回事。

**有两类东西不该让学生自己填**：① 特殊需求（残疾、疾病、宗教饮食、过敏）必须走辅导员正式通道并要求提供证明——自填会变成可钻的空子，而且本身是隐私；② 成绩、奖惩、家庭情况一律不收，它们和「能不能住到一起」无关，收了只是徒增风险。

> **为什么要 `--defaults-extra-file`**：MySQL 9.x 客户端在 `-p` 后面不接受「把口令写在命令行」的做法，逐个脚本交互式输口令在批量部署时极易出错。凭据文件用 `[client]` 段，权限设为只有部署账号可读；它不进版本库（`config/local.properties` 也是同理）。

> `nest_audit.sql` 必须**指定库名**（脚本里用 `DATABASE()` 做幂等判断）：
> 报 `ERROR 1046 (3D000) ... No database selected` 就是漏了 `nest`。
> 它也可以在任何时候重复执行（幂等），补审计表或补两列都安全。


> ⚠️ 注意：第 1 步 `nest_init.sql` 会 `DROP TABLE` 后重建，**只用于全新部署**。已有数据的库不要重跑它——升级前必须先 `mysqldump` 全库（见 §11 备份与回滚）。

⚠️ **`mysql -e` 里面不能用 `source`**：`source` 是 mysql 客户端的内建命令而不是 SQL 语句，写进
`-e "source 文件.sql"` 会在 MySQL 9.x 客户端报 `ERROR 1064`。三条可行写法：
1. 输入重定向 `... -D nest < sql\文件.sql`（推荐，见上）；
2. PowerShell 管道：`Get-Content sql\文件.sql -Raw -Encoding UTF8 | mysql --defaults-extra-file=... -D nest`；
3. 先不加 `-e` 直接 `mysql --defaults-extra-file=... -D nest` 进交互式会话，再敲 `source sql/文件.sql`（路径用正斜杠）。

### 每学期导入名单（以及导入会、不会动什么）

名单用 `POST /api/dorm/data/import` 导入。`students` 必须有，`rooms` 可以只在第一次给。
志愿字段用**学号**填（`"wantRoommateWith": ["S20230101"]`），不是数据库 id —— 真实学号带字母，
用数字表达不了；指向本次名单里不存在的人会被丢掉，并在体检报告里点名。
`buildingPref` 可以写一个楼栋，也可以写 `"S女生1号楼,S女生2号楼"` 这种多选。

**导入前先体检，体检不过整体拒绝、一行都不写。** 也可以先单独体检：`POST /api/dorm/data/preflight`，
它一个字都不写，适合正式导入前反复试。

被拦住的（ERROR）：学号重复（后面的行会覆盖前面的行，等于悄悄少一个人）、性别或特殊需求写了不认识的值、
同一栋楼里房号重复、房间容量不是正数、床位总数少于学生数、某个性别的床位少于该性别的学生数、
有特殊需求的学生多于特殊房床位、志愿里把自己写进去。
只提醒不拦的（WARN）：姓名或年级为空、特征数组长度不对、志愿指向名单里不存在的人、
房间容量大得可疑（>8，通常是误把楼栋床位数填进了单间）。

**导入只负责它带的那一部分，没带的一律不动：**

| 名单里的情况 | 结果 |
|---|---|
| 某人没有志愿 | 他在门户里自己填的志愿**原样保留** |
| 某人只有楼栋意愿、没有室友意愿 | 楼栋意愿被替换，他自己填的室友意愿**保留** |
| 某人带了室友意愿 | 「想同住 / 不想同住」这一类被替换成名单里的 |
| 某人没给特征数组 | 他做过的问卷和已提取的特征**原样保留** |
| `replaceAll=true` | 先清空全部宿舍数据再导 —— 这是**唯一**会全清的入口 |

> 为什么强调这条：学校每学期导一次名单，而学生的志愿和心理问卷是长期积累的。
> 早先的实现是「先清空整表再灌」，导一次名单就把全校学生填的志愿全删了；后来改成「只删被导到的这些人」，
> 但名单里通常没有室友意愿，于是又把这批人自己填的室友志愿删掉。现在替换粒度落在「学生 + 志愿种类」上。
> 名单里没有志愿的行应当理解为「这次导入没说他有什么志愿」，**不是**「他没有志愿」。

导入成功后返回体里会带一份体检报告（`preflight` 字段），提醒也一并交给管理员。

## 7. HTTPS 与 PWA（这条决定手机端能不能「装到桌面」）

浏览器的硬规定：**Service Worker 只在 HTTPS 或 `localhost` 下生效**。

| 部署方式 | 网页功能 | 添加到主屏 / 离线打开 |
|---|---|---|
| `http://内网IP:8080` | 完全可用 | ❌ 不可用（浏览器拒绝注册 SW） |
| `https://域名`（推荐） | 完全可用 | ✅ 可用 |
| `http://localhost:8080` | 完全可用 | ✅ 可用（仅本机调试） |

所以：
- **内网先用 HTTP 试功能没问题**，只是手机上不会出现「添加到主屏幕」。
- **要给学生用手机装成 App**，必须上 HTTPS。最省事的做法是前置一个反向代理（nginx / Caddy）申请
  校内 CA 或 Let's Encrypt 证书，再把 443 转到 8080。应用本身不用改一行代码。

反向代理要点：转发 `/` 全部路径，保留 `Host` 头，并放行 `Content-Type: application/manifest+json`
（应用已为该文件单独设置了正确的 MIME，代理不要覆盖）。

### 换了静态资源（JS / CSS）之后，用户为什么还能看到旧版

`/sw.js` 的取数策略分四类（2026-10-13 起）：

| 请求 | 策略 | 理由 |
|---|---|---|
| `/api/**` | 直连，不进缓存 | 接口数据必须实时 |
| `/sw.js` 自己 | 直连，不进缓存 | 否则页面自检 `fetch('/sw.js')` 会拿到缓存里的旧副本，量到的版本和真正在跑的那个不是一回事 |
| `/js/**`、`/css/**` | **先网络后缓存**，断网才回退缓存 | 否则「部署了新脚本、用户浏览器里还是旧的那一份」，看起来像改动没生效 |
| 其余同源静态资源 | 先缓存后网络（stale-while-revalidate） | 断网可用 |

「先网络后缓存」里的**网络那一步只认 200**：机房代理/网关超时时回的是一张 504 的 HTML
错误页，`fetch` 不抛异常但 `res.ok` 是 false —— 老版本会把这页 HTML 当成 JS/CSS 交给页面
（控制台只报一个含糊的「意外的 <」），还会写进缓存固化下来。现在这种情况与「网络抛异常」
同等处理，一律回退缓存。

所以改完 JS/CSS 重新部署，用户**刷新一次**就能拿到新版。`sw.js` 里的缓存名
（当前 `nest-shell-v4`，2026-10-14 起；上一版是 `nest-shell-v3`）每次改缓存策略、SHELL 清单或 `OFFLINE_URL` 都要换一个名字，旧副本才会被淘汰——换名字后
用户第一次访问会重新拉一遍静态资源，属正常现象。

### 怎么确认「装到桌面」和「断网能用」这两条路是通的

应用清单 `manifest.webmanifest` 与 4 个图标已经挂在**全部 48 个页面的 `<head>`** 里
（2026-10-18 实测 48/48；旧文档写「21 个页面」，那是教学页删除前的数字。2026-10-13 之前只有 3 个宿舍页挂了，其它页面点「安装到桌面」是灰的）。三条自查命令：

```powershell
cd D:\project\NEST
node tools\wire-pwa.mjs                          # 幂等：缺哪条补哪条（加 --dry 只预演不改文件）
node tools\run-flow.ps1 -Flow pwa -Sid <学生会话>  # 真断网跑一遍：清单、缓存、离线外壳
node tools\check-dom-ids.mjs                     # 全站页面的 id 引用对账（可吃目录），顺带确认页面没被改坏
```

> `check-dom-ids.mjs` 的路径参数直接传 `src\main\resources\static` 即可；`check-inline-js.mjs` 不同，**不吃目录，要一页一页传**。

第二条需要无头 Chrome 在 9222 端口（见 §8 的检查命令清单）。**测离线必须用 CDP 的
`Network.emulateNetworkConditions { offline: true }`**，也就是探针配置里的 `"offline": true`
或某一步里的 `{ "offline": true }`。如果改用 `Network.setBlockedURLs(['*'])`，它会连
Service Worker 内部发起的 `fetch` 一起拦掉，量出来必然是「离线时 JS/CSS 全丢」——这是
**假阴性**，本仓库早期就照它误判过一次。`tools/flows/pwa.json` 现在已经改成真断网。

**第 9 步在防什么（2026-10-13，第十轮）**：动效层（`/js/nest-motion.js`）会**先给元素加一个隐藏前态、

② 揭示线以上的视口里不存在停在 `.nx-appear` 却还没 `.nx-in` 的元素 —— 判定用的揭示线是观察者自己的 `rootMargin: '0px 0px -6% 0px'`，即 `vh-6%`，**不是视口下沿**（原先按视口下沿判，P12 那个 `top=847 / vh=900` 的卡片比线低 1px 就成了假失败；两条揭示机制 `nest-ui.js` / `nest-motion.js` 互不干扰）。

**第 10 步在防什么（2026-10-14，第十二轮）**：同一类控件在不同页面被写成了不同尺寸——根因是
`tools/webbuild/tailwind.config.js` 的圆角刻度**不是单调的**（`rounded-lg` 32px 竟比 `rounded-2xl` 16px 更圆）。
刻度已在配置里修正，页面里的存量写法由 `node tools\unify-ui.mjs --apply` 机械迁移到 `.nx-card` / `.nx-panel` /
`.nx-dialog` / `.nx-btn*` / `.nx-tab`（默认 dry-run，会打印命中处数与前后样例）。`check-unify.ps1` 就是这条约定的守卫：
它用 `chendw`/`lisi`/`admin` 等身份打开 **26 个页面**（见 `tools\check-unify.ps1:86-111`；旧文档写「8 个页面」是教学页删除前、P11/P12 之前的数字），断言每页上面板圆角 16px、弹窗 22px、按钮圆角 10px 且高度只在
{32,40,46}px、标签 12px，并顺带检查控制台干净。**以后新写页面请直接用这些组件类**，不要再手写
`rounded-xl border border-primary/10 bg-white/50` 那一套。

**第 11 步在防什么（2026-10-15，第十四轮）**：背景粒子层是「按页 opt-in + 懒加载」的：页面没有 `data-nx-particles` 就一行都不跑，
系统开了「减弱动态效果」就连那 158 KB 的库都不会下载，库下载失败也只是没有背景粒子、页面照常用。这一步能拦住的典型事故是
**「粒子盖住内容」与「隐藏的元素仍占位」**：断言每页恰好一个 canvas、它在 `z-index:-10` 且 `pointer-events:none`、
`prefers-reduced-motion` 下没有宿主元素也没有库请求。粒子层的手感（快慢、疏密）机器断言管不了，观感请自己看一眼。

**第 12 步在防什么（2026-10-15，第十五轮）**：`/art.html` 的背景是一层 WebGL2 着色器，这一步跑 30 条断言：着色器真的画出了像素（同一套 uniforms 分别用「缺尺寸 uniform」与「补齐」两种挂法，把像素读回来对比）、字体真的生效（两个 `@font-face` 状态为 `loaded`、两个 woff2 真的被取过、同一串文本的宽度与通用 `serif` 不同）、主题与动效开关真的切换了页面、无 WebGL2 时退成静态径向渐变、375px 无横向溢出、系统「减弱动态效果」下 hero 帧数恒为 0 且内容 31/31 立即显示、四份探针控制台干净。**为什么这条必须有**：这一轮抓到过一个教科书级的静默失败 —— 少传一整套「尺寸 uniform」时，顶点阶段 `v_objectUV /= u_scale` 除以 0，片元输出整张透明，而**页面照旧好看、控制台一句报错都没有**，只有把像素读回来才看得见（细节见《课堂管理系统-功能补全说明》§20.4）。

**第 13 步在防什么（2026-10-15，第十七轮）**：这一轮把整站视觉换成了另一套令牌，同时给 6 个入口页加了一层 WebGL 背景。
两类缺陷只有它能拦住：① **「改了本地、服务的是旧的」** —— 静态资源要先复制进 `target/classes` 才会被服务，
这一轮真的踩了（`nest-shader-bg.js` 改了 `themeOf()` 却忘了同步，页面一直跑旧逻辑，而两次探针都过）；
所以断言里有一条是**逐文件比对 src 与 `target\classes` 的 SHA256**。② **降级路径只在极端环境才走到** ——
系统开了「减弱动态效果」时着色器必须 `speed=0` 且帧号不前进、粒子连 158 KB 的库都不下载，
浏览器断网时这一层必须从 Service Worker 缓存里照常起来；这些用命令行没法感知，只能由探针去点。
**这一轮删掉了 9 个页面里手写的 CSS 粒子**（共 94 个元素，每个挂一条 `float-fast` 无限关键帧）：它们已被同一层 canvas 取代。
删除由 `node tools\strip-legacy-particles.mjs` 完成（默认 dry-run；每页删掉的元素数必须与登记数字完全相符，任何一处不符就整体不写盘）。

**第 14 步在防什么（2026-10-16，第十八轮）**：
> ⚠️ 这一步的脚本 `tools\check-daisy.ps1` 已在 P8 删除（它断言的两个样板页之一「学生工作台」仍在，`teacher-dashboard`/`admin-dashboard` 也仍在，但脚本本身没了）。下面记的是它当初防的两类缺陷，**现在其中「daisyUI 令牌串味」这条已无人自动断言**。

这一轮开始把页面**逐页重画**（用户要求整站重做），引入了成熟设计系统 daisyUI。
两类缺陷只有它能拦住：① **同一套设计系统里两个控件共用一个令牌** —— daisyUI 的 `--rounded-btn` 同时管按钮和 `.input/.select/.textarea`，
第一版把它设成 999px 想让按钮保持胶囊，结果**登录页的文本框也成了胶囊**（探针读数 `input=999px`）；
所以断言里 `.btn` 必须是 999px、`.input` 必须是 10px，两条一起验。② **换了类名就静默丢掉旧效果** ——
第 10 轮的「鼠标光斑 + 磁性微移」挂在 `.nx-btn` 上，页面改用 daisyUI 的 `.btn` 之后 `check-motion.ps1` 立刻失败；
这一轮把动效层认的类名扩到了 `.btn`，恢复由断言证明，而不是「看起来没坏」。

**第 15 步在防什么（2026-10-16，第十九轮）**：这一轮加了「登录失败锁定」（连错 N 次锁 M 分钟），
真机冒烟却打出一件**完全静默的失效**：连错 5 次密码仍然全部返回「用户名或密码错误」，第 6 次用正确密码直接登录成功 ——
根因既不在策略代码也不在 SQL：`UserMapper.xml` 的结果映射与列清单**没有带 `failed_login_count` / `locked_until`**，
于是 `User.failedLoginCount` 恒为 null、计数永远停在 1，锁定分支永远走不到，而**没有任何错误、日志或异常**。
Mockito 单测看不见它（mock 直接返回造好的对象），只有真机点得出来。
`check-mapper-columns.mjs` 就是这条形态的守卫：读 `entity/*.java` 的字段，要求每个字段的列出现在
**「能读出来」**的位置（`<sql>` 片段、`<result column>` / `<id column>`、`AS 别名`）——
**UPDATE 的 SET 列不算**（只写得进、读不回来的列正是要抓的东西）。改实体或 Mapper 之后请跑它一次。

要看**运行起来**的样子（真浏览器，断言无控制台错误、命令面板能开、暗色刷新不闪白）：

`offline-pages.ps1` 删三样东西：Google Fonts 的 `<link>`、Tailwind CDN 的 `<script>`、

`ReferenceError: tailwind is not defined`，而页面看上去「能显示」，只有打开控制台才看得见。
有页面写的是 `<script id="tailwind-config">`，脚本已兼容这种写法。

## 10. 已知限制（如实列出）

1. **鉴权只做到接口级粗粒度**：`SecurityConfig` 对所有请求 `permitAll`（申请书的 MoSCoW
   里「精细权限」本来就写在 Won't）。宿舍模块另有一道拦截器：`DormStaffInterceptor` +
   `DormAccessConfig` 把 `/api/dorm/**` 中除 `/api/dorm/portal/**` 与 `/api/dorm/health`
   之外的全部接口，要求会话角色落在 `nest.dorm.staff-roles`（默认 `admin`）里，未登录 401、
   角色不符 403。也就是说：**学生接口靠会话自证、宿管接口靠角色白名单**。
   至于「哪个学生能看哪个学生的心理画像」这类**数据级**授权：学工各模块**已经按模块
   落地在服务层**（本人 / 名下学生 / 同宿舍 / 管理员，拒绝文案含「无权」，返回 403），
   逐条清单与复查工具有 `docs\权限与数据级授权审计.md` + `tools\authz-audit.mjs`
   （22 控制器 / 151 路由 / 四张表，可反复跑）。
   框架层另有一道**按路径的角色粗筛**（2026-10-20 补）：`ApiRoleGuardInterceptor` +
   `ApiRoleGuardConfig` 挂在 `/api/**` 上，按 22 条规则拦「只有员工 / 管理员在用」的面 ——
   `/api/admin/**` 只放 `admin`（前缀匹配，往管理端新增接口自动受保护）；
   `/api/counselor/**` 与各模块的 `review` / `export` / `manage` / `batches` 等 21 条只放
   `admin` + `teacher`（`nest.api.admin-roles` / `nest.api.staff-roles` 可改，写空回落出厂值）。
   拒绝时回 HTTP 200 + `code 401/403`，并打一条 WARN 日志（方法 / 路径 / 角色）。
   **仍然没做的是**：① 完整 SecurityContext 鉴权（`/api/**` 在 `SecurityConfig` 里仍全
   `permitAll`；不能直接改 `hasAnyRole`——这套代码没有 SecurityContext 身份，改了会锁死所有人，
   见审计文档 §7）；② 学生也要用的双用途路径（如 `/api/honor/batches`、
   `/api/community/inspections/{id}`）的框架层保护，它们的归属判断只能留在服务层（§7.1 写了原因）。
   粗筛本身的复查入口：`node tools\verify-api-guard.mjs`（30 条断言，末行给 VERDICT）。
2. **学生端依赖会话**：`/api/dorm/portal/**` 未登录时返回 **HTTP 401**
   （`{"code":401,"message":"LOGIN_REQUIRED 未登录，请先登录学生账号。"}`），前端据此跳登录页。
   （早期版本这里错返回 500，已修：新增 `LoginRequiredException` +
   `GlobalExceptionHandler` 里的 401 分支。保留说明是为了让排查的人知道
   `LOGIN_REQUIRED` 这个前缀是前端依赖的契约，不要改。）
3. **申诉是局部重解**，不是全局重解；界面上已有「在我找过的范围内不能满足」这种如实表述，
   不承诺一定满足。

## 11. 备份与回滚

> **这台开发机没有 git**（`D:\project\NEST\.git` 不存在），所以回退只能靠两样东西：**目录级备份**与**数据库转储**。每次动代码/文档/脚本之前先备份，是这套流程里唯一的安全网。

### 11.1 代码与文档的备份

改动前把要动的目录整份复制到 `target\backup-<主题>\`（`target\` 不参与交付、也不被静态资源扫描）：

```powershell
# 例：改动 docs 之前
Copy-Item -Recurse -Force D:\project\NEST\docs D:\project\NEST\target\backup-docs-<主题>
# 例：改动静态页之前
Copy-Item -Recurse -Force D:\project\NEST\src\main\resources\static D:\project\NEST\target\backup-<主题>
```

**既有备份可以对照/取用**（`D:\project\NEST\target\` 下 33 个 `backup-*` 目录，2026-10-14 实测）：

| 目录 | 备份的是什么 |
|---|---|
| `backup-p8-teaching\` | P8 教学模块下线**之前**的代码与页面（要找回已删教学页就从这里） |
| `backup-xuegong-pre\`、`backup-xuegong-rename\` | 「课堂管理系统」→「学工平台」**改名之前**的版本（品牌回退用这个） |
| `backup-dash-redesign\`、`backup-teacher-course\`、`backup-<各页面名>\` | 各轮整页重画之前的版本（`backup-dash-redesign` 是登录页/学生工作台 daisyUI 重画前的） |
| `backup-docs-*` | 各轮文档改动前的 `docs\` |
| `backup-p11\`、`backup-p11b\`、`backup-p11c\` | P11 困难认定复议各步骤之前的状态 |

**回滚代码/文档** = 把备份目录复制回去（`Copy-Item -Recurse -Force <备份>\* <目标>\`），再按 §12 第 4、5 步重建静态资源并重新编译。**注意**：备份是整目录快照，复制回去会**覆盖**该目录下所有当前内容，请先确认你要回退的范围。

### 11.2 数据库转储（每次升级前必做）

`mysqldump` 已随 MySQL 9.5 装在 `D:\develop\mysql-9.5.0-winx64\bin\mysqldump.exe`（**不在 PATH 上，要用全路径**）。凭据复用 §3 建好的 `%TEMP%\nest_my.cnf`：

```cmd
cmd /c ""D:\develop\mysql-9.5.0-winx64\bin\mysqldump.exe" --defaults-extra-file=%TEMP%\nest_my.cnf --single-transaction --routines --triggers --default-character-set=utf8mb4 nest > D:\project\NEST\target\nest-backup-20261014.sql"
```

> ⚠️ **一定要用 `cmd /c` 的 `>` 重定向，不要用 PowerShell 的 `>` 或 `Out-File`** —— PowerShell 5.1 的重定向默认写成 **UTF-16LE**，中文会变成乱码，恢复时才发现。`--single-transaction` 保证热备一致性（不清空、不锁表），`--default-character-set=utf8mb4` 保证中文不乱码。

**既有备份示例**：`D:\project\NEST\target\nest-backup-before-p8.sql`（**9,957,690 字节**，P8 教学模块下线前的全库转储，2026-10-14 实测仍在）。要回到「还带教学模块」的库状态，就恢复它——**但那也意味着教学页/教学接口要一起回退**。

### 11.3 恢复数据库

```cmd
:: 1) 建一个干净的库（如已存在先删）
cmd /c ""D:\develop\mysql-9.5.0-winx64\bin\mysql.exe" --defaults-extra-file=%TEMP%\nest_my.cnf -e "DROP DATABASE IF EXISTS nest; CREATE DATABASE nest DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;""
:: 2) 倒入转储
cmd /c ""D:\develop\mysql-9.5.0-winx64\bin\mysql.exe" --defaults-extra-file=%TEMP%\nest_my.cnf -D nest < D:\project\NEST\target\nest-backup-20261014.sql"
```

> 恢复 `nest_init.sql` 那类含 `DROP TABLE` 的脚本与本流程**不冲突**：它们只操作 `nest` 库内的表，不动库本身。

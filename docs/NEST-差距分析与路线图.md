# NEST 差距分析与路线图

> 这份文档回答用户的问题：「查看我们的软件距离完成还差了什么」。
> 方法：**先竞品取证，再自家盘点，最后逐项判定差距**；所有竞品结论都来自实抓的公开来源（正文标 `[n]`，来源清单见 §8），抓不到的一律写明「未查到／待核验」，**不凭印象写功能名**。
> 本文只做分析与排序，不含实现代码；实现在后续批次里按本文 P0→P2 推进。

- 文档版本：v1（2026-10-16）
- 对标范围：国际 LMS（Open edX / Moodle / Canvas / Blackboard / Teams for Education）、国内教学平台（超星学习通 / 雨课堂 / 云班课 / 智慧树 / ClassIn / 钉钉）、开源宿舍系统（GitHub 高星 7 个）、校方真实业务文件（宿舍采购公告、房型意愿征集通知、学生申诉办法）、监管与验收材料（等保测评指标、教育 APP 备案细则、大创结题验收通知）。

## §1 最重要的一条结论

**GitHub 高星宿舍系统（1462★ / 401★ / 344★ / 330★ / 172★ / 144★ / 108★）的模块清单全部是 CRUD 记录管理**——学生管理、楼栋、宿舍、调宿、报修、水电费、卫生检查、考勤、访客、公告。**没有任何一个实现「志愿填报 + 算法分配 + 可解释性报告」**。[22]–[29]

而校方真实流程至今仍在用**问卷平台 + Excel + 腾讯会议直播抽签**手工完成：上海交通大学集成电路学院 2026 级博士新生宿舍房型意愿征集通知里，规则原文是「第一至第五意愿排序、仅可提交一次、截止前可用修改链接修改、公开随机抽签确定房型分配次序（腾讯会议直播、可监督）、按抽签次序依次处理、轮到某人时按其第一至第五意愿顺序查看各房型剩余床位、分配当时仍有床位的最高顺位、未提交视为服从分配」。[31]

⇒ **NEST 的差异化不是「更全」，而是「能解释」。** 这条结论决定了后面的排序：先补齐「能不能交付给学校用」（合规与基础盘），同时把可解释、公平性、最优性验证做成**别人没有的护城河**。

## §5 差距清单（按优先级）

判定口径：**P0 = 学校真要用就必须有（合规/交付底线）**；**P1 = 教学与宿舍业务闭环缺的那几块**；**P2 = 加分项**。

### P0 — 合规与交付底线
| # | 差距 | 依据 | 验收方式 |
|---|---|---|---|
| P0-1 | **审计日志**（时间/用户/事件类型/成功与否/来源 IP） | 等保原文 [39][40]；竞品无此模块 [23]–[26] | 新增 `audit_log` 表 + 过滤器 + 管理端查询与 CSV 导出；单测 + 端到端断言 |
| P0-2 | **密码复杂度 + 定期更换 + 登录失败锁定** | 等保原文 [39][40] | 服务端校验器 + `failed_login_count/locked_until`；单测覆盖边界 |
| P0-3 | **权限矩阵（角色×资源×操作）+ 数据级授权** | 采购协同要求 [30]；Canvas 细粒度 [6] | 接口级注解 + 资源归属校验（课程成员/教师本人）；越权用例测试 |
| P0-4 | **SSO / 统一身份认证对接点** | 采购「须对接」[30] | 可插拔认证适配层（CAS/OAuth2 接口 + 本地回退）+ 对接说明文档 |

## §6 差异化护城河（建议重点强化，已有基础）

1. **可解释决策**——竞品零解释能力（§1）。把「为什么这位同学分到/没分到某房型」做成结构化报告：志愿顺位、当时剩余床位快照、命中的约束、被谁挤占、最终得分分解。
2. **公平性证明**——对标校方「公开抽签的程序公平」[31]，输出量化指标：志愿满足率、最差个体顺位、与随机基线对比；理论依据引用稳定匹配与 egalitarian stable matching [47]。
3. **CP-SAT 最优性验证**——用求解状态（OPTIMAL/FEASIBLE/INFEASIBLE）作为最优性证据 [45][46]；与校方规则原文的贪心基线（按次序扫描志愿取最高可用顺位 [31]）做**量化改进对比**，这是评审最容易打高分的技术点。
4. **决策链路可重放**——随机种子、参数版本、规则版本、参与者名单全部留痕，支持同一次分配的完整重放与第三方复核（填补竞品空白）。
5. **室友生活方式匹配**——全球同类原型仅 dormmatch-ai [49]，校方现状「不支持跨学院、分配后另行通知」[31]。

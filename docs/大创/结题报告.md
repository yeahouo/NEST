## 一、研究背景与问题

### 1.1 需求不是自己设想的，是改造任务倒逼出来的

本系统的前身是一套课堂教学管理系统。立项后期，指导老师明确要求把它从「学生管理系统 / 课堂管理系统」改造为**学工平台**，并给出三条口径：真做学工业务模块、整体改名为学工平台（弃用 CodeClass）、彻底移除教学模块〔出处：docs/学工平台改造路线图.md:3-7〕。这一条决定了本项目的问题域不是「宿舍算法」单点，而是「学生工作 + 宿舍分配」两块：

- 学工侧要覆盖学校真实发布的业务，且**只对齐能查到出处的业务**；查不到出处的（学校内部系统界面、私有字段）明确写「无从考证」，不编造〔出处：docs/学工平台功能对齐说明.md:3-4〕。
- 宿舍侧要保留原有的「宿舍智能分配与可解释决策支持」能力，作为学工平台的一个子模块〔出处：docs/学工平台改造路线图.md:16-21〕。

### 1.3 宿舍分配这一侧的真问题

学校现行做法有四类：按学号顺序、按班级/专业切块、学生自选室友后系统凑房、宿管手工微调。四者的硬约束都能满足，但软目标与可解释性差别很大——**宿管手工微调的可解释性是它唯一、也是决定性的优势**：任何自动化方案要真正取代手工，必须先在可解释性上至少持平，否则管理员没有理由交出决策权〔出处：docs/结题材料/结题报告.md:88-95〕。

学术侧的三条主流路线各有硬伤，这也是本项目选型的原因（原文的取舍理由）：

- 多目标进化算法（遗传/粒子群/NSGA-II）：能给出 Pareto 前沿，但**不可解释、不可复现**（同一输入两次运行结果可能不同），管理员无法把「随机跑出来的一组宿舍」交出去〔出处：docs/结题材料/结题报告.md:101〕。
- 稳定匹配（Gale-Shapley 及变种）：标准形式假设每个学生对每个房间排序、房间容量为 1；现实是 4 人间、且要求「同一房间内的人互相合得来」，属于多对多分组稳定性，且稳定解往往不存在。本项目改为**可计算的阻塞对计数**作为代理指标〔出处：同上:102〕。
- 机器学习预测配对：需要历史标签，而历史数据正是「按学号排」的产物，拿它训练等于把现有做法的偏见学一遍〔出处：同上:103〕。

因此本项目的定位是**一条「确定性的、可解释的、代价可见的」决策支持链路**，而不是在人为目标函数上刷分〔出处：docs/结题材料/结题报告.md:105〕。

### 1.4 一个必须如实交代的组织事实

学校 `users.role` 只有 `student / teacher / admin` 三种，**没有「辅导员」角色**；从 P3 起把 `teacher` 的语义定为「辅导员」〔出处：docs/学工平台改造路线图.md:645〕。这条事实直接决定了后面所有权限矩阵的写法，也是答辩时容易被问到的点。

### 2.4 宿舍分配内核

- **求解链路**：块分解（利用硬约束把问题拆成互相独立的子问题）→ 贪心构造 → 带桶守卫的局部搜索 → 阻塞对修复；算法标识 `nest-block-greedy-ls-repair-v1`〔出处：docs/实验与验证.md:32-39〕；五类硬约束（性别、楼栋、年级、特殊房型、容量）在全部实验中 100% 可行、无一人未分配〔出处：docs/结题材料/结题报告.md:20；docs/实验与验证.md:75〕。
- **相容度模型**：11 维特征上的两两打分，8 个打分维度的默认权重为 作息 .20 / 吸烟 .20 / 卫生 .14 / 外向 .10 / 学习噪声 .14 / 游戏噪声 .10 / 社交 .06 / 共享 .06；`ambition` 不计分〔出处：docs/创新点-不确定感知的宿舍分配.md:26-42〕。
- **缺失语义（本项目的核心改动）**：`c_ij = Σ_d w_d·c̃_d(i,j)`，`c̃_d = c_d`（双方第 d 维都已知）或 `0`（任一方未知），即「没回答 = 中性，不是好」〔出处：docs/创新点-不确定感知的宿舍分配.md:26-42〕；实现在 `RuleBasedCompatibility.java:24-33`（刻意删掉了 `imputed(mean)` 那一行）〔出处：同上:42〕。数据库层把缺失存 SQL `NULL`，读出还原 `Double.NaN`——「没回答」≠「打 0 分」〔出处：docs/给学校的部署说明.md:39〕。

## 三、创新点：缺失感知的分配（MAA）

### 3.1 三条可证伪命题

项目把「问卷可能残缺」当成一等公民，而不是先插补再计算，并把这件事拆成三条各自配有对照实验的命题〔出处：docs/创新点-不确定感知的宿舍分配.md:24、20〕：

| 命题 | 内容 | 可证伪的对照 |
|---|---|---|
| **H1 缺失语义** | 任一维未知时该维贡献记 0（中性），而非用总体均值补齐 | 「均值补齐 vs 未知中性」的分配结果对照 |
| **H2 可评估性门限** | 证据覆盖率 `Cov` = 同房对「双方都已知的维度权重」均值；可评估率 `Eval` = 至少一维可比的同房对占比。`Cov < 0.15` 或 `Eval < 0.5` 时不应把分数当结论 | Cov / Eval 与真值误差的单调性 |
| **H3 信息价值 VOI** | 每格补采的期望增益 `Δ_{i,d} = w_d·(1/|C(i)|)Σ_{j∈C(i)} E_{v~D_d}[c_d(v,x_jd)]·1[x_jd known]`，用于排「先问谁、问哪题」 | VOI 选 10% 预算 vs 随机选 10% |

命题与对照的设计理由是：论文里「准则没填」会退化成 ties，而真实问卷的缺项是「观测没采到」，数学上不是同一件事〔出处：docs/创新点-不确定感知的宿舍分配.md:18〕；因此三条命题各自都要有能被打败的实测口径〔出处：同上:84〕。

### 3.2 三条实测结论（数字照抄实验记录）

实测口径：合成数据，n=200、4 人间、观测噪声 0.20、特征缺失率 0.50、10 个种子，全部指标在隐真值上计算〔出处：docs/创新点-不确定感知的宿舍分配.md:141-143〕。

**结论一（H2/P3 成立）：缺失率越高，分数越没有证据。**

| 缺失率 | Cov | Eval | 零证据同房对 | MAE |
|---|---|---|---|---|
| 0.00 | 1.000 | 1.000 | 0 / 268 | 0.0985 |
| 0.25 | 0.481 | 0.997 | ≈1 / 267 | 0.3556 |
| 0.50 | 0.200 | 0.876 | ≈32 / 268 | 0.5105 |
| 0.75 | 0.056 | 0.407 | ≈159 / 268（**59%**） | 0.5979 |

〔出处：docs/创新点-不确定感知的宿舍分配.md:147-154、190〕读法照原文：缺失 25% 时九成以上的相容度权重仍是空的（Cov 0.481），缺失 75% 时六成同房对「一维都不可比」却照样被打分、被解释——门限要拦的不是「分数不好看」，而是「分数没有证据」〔出处：同上:154〕。

**结论二（H3/P1 成立）：同预算下 VOI 比随机更会挑格子。**

| 配对差（10 种子） | 均值差 | 为正的种子数 |
|---|---|---|
| `voi − none` | **+0.0021 ± 0.0060** | 6/10 |
| `voi − random` | **+0.0039 ± 0.0074** | 8/10 |
| `mean − none` | −0.0001 ± 0.0043 | 5/10 |

〔出处：docs/创新点-不确定感知的宿舍分配.md:169-171、188〕预算扫描（10% / 30% / 60%）上 `voi − random` 分别为 +0.0031 / +0.0053 / +0.0077〔出处：同上:176-182〕。原文同时给了这条结论的限度：10% 预算只补 103/1029 格，且 200 人里有 117 人的室友因此改变（59%），说明结论是「VOI 更会挑格子」而不是「补 10% 就提升质量」〔出处：同上:188〕。

**结论三（H1 的方法学结论）：插补能把 MAE 刷低，却买不到决策价值。**

`mean` 臂的 MAE 最低（**0.4228**，比 `voi` 的 **0.4365** 还低），但其分配收益与不补采无法区分（−0.0001 ± 0.0043），且「最差那对」在三个预算档上都是 `mean` 最差（0.1525 / 0.1483 / 0.1616）〔出处：docs/创新点-不确定感知的宿舍分配.md:163、182、189〕。P2 因此被判为「无可测收益」而非「主动损害」〔出处：同上:189〕。

### 3.3 创新点已产品化（不只是实验脚本）

`dorm-admin.html` 新增第 8 个 tab「补采建议」，背后是 `dorm/eval/MissingnessAdvisor.java`（coverage / cellTallies / rank）与 `dorm/service/MissingnessService.java`（只读，不读 `dorm_ground_truth`、不写表），两个接口 `GET /api/dorm/missingness/summary?batchId=`、`GET /api/dorm/missingness/priority?limit=`，受 `DormStaffInterceptor` 保护（默认仅 admin）〔出处：docs/创新点-不确定感知的宿舍分配.md:210-227〕；〔docs/给学校的部署说明.md:661〕。该增补**不新增页面 / 不新增 SQL / 不改 CSS**〔出处：docs/给学校的部署说明.md:1041〕。

### 3.4 与「一次自我纠错」的关系

创新点的由来是一次被自己抓到的评估偏差：原模型用总体均值补齐缺失特征，等价于把「没回答问卷」算成「很合得来」，于是**越不填问卷越被判定为志同道合**。改成正确语义后，NEST 在缺失数据上的绝对表现下降 3~4 个百分点，相对基线的领先随缺失率单调缩小（n=5000 时对 B2 的领先由缺失 0% 的 +1.46% 收窄到 25% 的 +0.75%、50% 的 +0.33%）〔出处：docs/实验与验证.md:127-149、414〕。旧模型下那些更漂亮的数字，是系统在给自己发奖——这条如实写进结题材料，不用来夸大效果〔出处：docs/结题材料/结题报告.md:35〕。

## 五、不足与边界

按「宁可写少、不写假」的原则，以下每条都给出处；没有出处的写【未能核实】。

1. **缺失语义尚未用于跨专业混住决策。** MAA 的实验与产品化都发生在「同专业块内」：主实验是 4 人间块内分配、E-A/E-B 的配对集合也是块内同房对〔出处：docs/创新点-不确定感知的宿舍分配.md:141-143、88-114〕；而「同专业集中住宿」是政策要求，去掉分块后每项指标都会变好（均值 +2.2%、志愿满足率约 2.9 倍、阻塞对 −18%、最差那对好 6 倍），代价只有 80 ms vs 40.8 ms——分块不是为更优、是为符合管理要求〔出处：docs/实验与验证.md:173-202〕。跨专业混住本身在本项目里**不宣称创新**〔出处：docs/创新点-不确定感知的宿舍分配.md:118-129〕，缺失语义如何迁移到跨专业场景没有做过实验。
2. **均值插补对照的限度。** 对照实验里 `mean` 臂的 MAE 反而最低（0.4228 vs `voi` 0.4365），但买不到决策价值；该结论只有 10 个种子、单一规模（n=200、4 人间），且 VOI 是一次性批量选择而非序列更新，因此**不能声称最优催填顺序**〔出处：docs/创新点-不确定感知的宿舍分配.md:189、202-208〕。
3. **缺失感知实验的收益是「上界」。** 补齐值取隐真值 `g`（等价于学生如实作答且不含观测噪声），所以测出的是收益上界，不是期望收益〔出处：docs/创新点-不确定感知的宿舍分配.md:74、202-208〕。另有第 3~4 位小数级别的波动，因为 `NestSolver.java:61` 用 `nanoTime` 时间预算〔出处：同上:184、208〕。
4. **没有短信/邮件网关，通知的最后一公里是假的。** `pom.xml` 无任何 mail/sms 依赖；`service/VerifyCodeService.java:81` 注入的 `VerificationCodeSender` 唯一实现是 `verify/LoggingVerificationCodeSender.java`（`delivers()` 返回 `false`），验证码**只写日志**〔出处：docs/学工平台功能对齐说明.md:144〕；对外表述因此不能写「短信/邮件通知」〔出处：同上:144；docs/给学校的部署说明.md:253、647〕。心理健康模块的「开始前 10 分钟发会议室号」「提前半天短信确认」同样无路由无字段〔出处：docs/学工平台改造路线图.md:525〕。
5. **X5：两处 LLM `base-url` 指向 `https://api.deepseek.com`，离线内网不可达。** 断外网时心理特征提取与宿舍分配的可解释文本降级到本地规则提取器〔出处：docs/学工平台功能对齐说明.md:143；docs/给学校的部署说明.md:56-57、284〕；另 `application.properties` 的 `nest.verify.pepper` 仍是出厂值，上线前必改〔出处：docs/学工平台功能对齐说明.md:143；docs/给学校的部署说明.md:229〕。
6. **P18 第二课堂成长手册：校内是否实施未能核实。** 成长手册栏目仅 6 篇，全文无「第二课堂」「学分」「学时」字样；S26 是共青团中央文件（转载，非一手），其数值由学校自定、部级文件无量值——因此 P18 必须**先向学校确认是否实施**再动手〔出处：docs/学工平台功能对齐说明.md:38-39、127；docs/学工平台改造路线图.md:624〕。
7. **数据级授权未做。** 鉴权只做到接口级粗粒度（申请书的 MoSCoW 口径），「谁能看谁的心理画像」这类数据级授权没有实现〔出处：docs/给学校的部署说明.md:728〕。等保合规这轮只做完三件（审计 / 密码策略 / 登录失败锁定），管理端界面、密码定期更换、数据级授权仍欠〔出处：同上:892〕。
8. **CP-SAT 只覆盖小规模，且不参与线上分配。** n=200 能证明最优（5/5，平均间隙 2.54%），n=400 在 120 秒内只能给间隙下界 1.45%，变量预算上限 15000，OR-Tools 在 JDK 17/23 下会 `EXCEPTION_ACCESS_VIOLATION`，跑实验须 JDK 25〔出处：docs/给学校的部署说明.md:749-758；docs/实验与验证.md:276-301〕。另需注意：2.54% 是**在模型目标上**的间隙，不是真实相容度〔出处：docs/实验与验证.md:330〕。
9. **实验全部在合成数据上，且未测并发。** 隐真值 `g` 含算法看不见的磁铁效应项、睡眠交互项与 `ambition` 权重 0.12，因此「把 `g` 优化到全局最优」在信息上不可能；七条边界中还包括：最差那对主实验只 +3.2% 不显著、木桶压力项无可测量效果、特征提取样本仅 8 名学生、全部实验离线求解未测并发与幂等〔出处：docs/实验与验证.md:19-26、320-342〕。
10. **两处工程口径不一致（如实登记）。** 楼栋意愿存了两处，门户里改的那次不会同步到 `dorm_student.building_pref`〔出处：docs/给学校的部署说明.md:760-766〕；申诉是局部重解而非全局重解〔出处：同上:739〕。
11. **前端仍有历史欠账。** 原生 `alert/confirm/prompt` 尚有 21 处分布在 9 个文件、部分触控目标 <44px、整站视觉重做只完成 login + dashboard 两页样板〔出处：docs/给学校的部署说明.md:816-826、885-891〕。
12. **项目周期与经费** 在仓库内无任何记录【未能核实】；已实施阶段的学校侧验收意见、真实学生规模试点报告同样【未能核实】。

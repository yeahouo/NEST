# 统计某一目录下指定后缀的文件数与总行数
function Stat2($dir,$filter){
  $files = Get-ChildItem -Path $dir -Recurse -File -Filter $filter -ErrorAction SilentlyContinue
  $tot = 0
  foreach($f in $files){
    $tot += (Get-Content -LiteralPath $f.FullName -Encoding UTF8 -ReadCount 0).Count
  }
  [pscustomobject]@{ dir=$dir; ext=$filter; files=$files.Count; allLines=$tot }

## 四、主要功能

系统按 17 个阶段落地（阶段名照抄改造记录〔docs/学工平台改造路线图.md:606-623〕），功能如下。

**1. 平台品牌与学工口径收敛（P1/P8）**
把原课堂教学管理系统整体改造为「学工平台」：品牌改名 78 处 / 30 个文件，教学模块彻底下线（删 5 页 + 64 个后端/测试文件、DROP 11 张教学表），公告改为全校口径。平台从此只承载学生工作业务，导航、审计常量、测试基线都按学工口径重建。

**2. 学工数据模型（P2）**
建立请假、学生档案、奖惩、资助、综测等 7 张基础表与 17 项综测指标（五维权重各 1.0000），并提供对应实体与 Mapper；两遍幂等验证通过。该模型是后续所有学工模块的共同底座。

**3. 学生档案与辅导员学生名册（P3）**
学生可查看/维护本人档案（`/api/student/profile` GET/PUT）；辅导员可按 `student_profile.counselor_id` 查看名册、详情、修改与补建（`/api/counselor/students`）。未分派时按全校可见，避免「没分派就什么都看不到」。

**4. 请假与离校审批闭环（P4）**
学生提交请假（事由、去向、联系方式、起止时间），辅导员审批通过/驳回，学生销假，状态机 `pending→approved→closed`、`rejected`、`cancelled` 全部带 from 条件 CAS 更新，杜绝并发覆盖。列表支持全部/待审批/已批准/已销假四档筛选。

**5. 奖惩与资助（P5）**
管理员录入学生奖励与处分（`/api/award-punishment`），学生提交资助申请、辅导员/管理员审批（`/api/aid`）。资助含困难认定、助学金、临时补助三类，审批留痕进审计表。

**6. 综合素质测评（P6）**
按五维（德 0.25 / 智 0.35 / 体 0.15 / 美 0.10 / 劳 0.15）组织指标库与权重，学生自评、系统汇总、生成排名。权重可配置并在页面标注口径，公式写入文档。

**7. 辅导员工作台（P7）**
聚合待办、异动预警与学生画像三块：预警六类按级别排序（① 学籍异常 high ② 逾期未销假 high ③ 近 30 天请假 ≥3 次 medium ④ 本学期综测未出分 medium ⑤ 资助积压（`pending` 超 7 天）medium ⑥ 档案未建 low），画像按学生维度汇总请假、奖惩、资助、综测记录。全部为只读接口，不新增审计类型〔docs/学工平台改造路线图.md:252〕。

**8. 勤工助学（P10）**
岗位发布（含计酬标准、工时上限）、学生申请、面试与录用、工时登记与审核、酬金结算，依据《勤工助学管理办法（2021 年）》逐条落地。管理端修掉了「列表硬编码当前学期」的真机缺陷（学期不传即不过滤）。

**9. 家庭经济困难学生认定（P11）**
两档级别 + 八步程序 + 公示 + 复议 + 学期复查，八步状态机全 CAS；公示 5 个工作日、异议走复议台账（`aid_objection`）。两处接口加固（公示匿名访问 401、取消资格理由仅限角色 403），非法路径变量不再 500。

**10. 评奖评优在线申报（P12）**
批次管理 → 学生申报 → 三级审核 → 公示 → 名单导出。审核意见做空话白名单（「同意推荐」这类只写结论的会被 400 拒绝）；五项自动核验（综测排名 / 荣誉次数 / 体测 / 不及格 / 违纪）；公示按工作日折算；导出 CSV 带 BOM 且不含学生自述。

**11. 综合素质测评排名公示与导出（P13）**
A 台账（学习成绩）与 B 加分申报审核分离，`M = A + B`、`B = C × μ`、`μ ∈ [0.5, 0.7]` 钳制；生成排名快照与等级落位，公示后受理异议，支持导出。加分审核覆盖七大类。

**12. 心理健康（P14）**
普查批次与量表、关注台账、预约咨询、转介四块，8 张 `psyche_*` 表、32 条方法级路由。**不做量表计分诊断**，等级只能回填不得自动推导；学生端不下发等级原文与中心内部备注（服务端抹掉）；列表脱敏，关注/转介仅 admin 与该生辅导员可见；预约规则为「提前一个工作日 + 周一至周五 8:00-17:00（含边界）+ 默认 50 分钟 + 续约沿用原咨询师」。

**13. 社区管理（P15）**
安全卫生检查评分、晚归与夜不归宿登记、违规台账、社区活动、文明宿舍评比，7 张 `community_*` 表、40 条方法级路由，状态机全 CAS。依据《学生园区管理规定（2019 年 7 月修订）》，晚归判定窗口 6:00–23:30。

**14. 学生党建（P16）**
发展党员五阶段台账、党校培训与结业、公示、材料清单，7 张 `party_*` 表、38 条方法级路由。**不做自动资格判定**；阶段推进必须显式前置态 + CAS；公示 5 个工作日且异议只写校级渠道；材料只登记不落二进制；学生对本人清单只读；导出带 BOM 且学号脱敏。

**15. 校园文化：志愿服务时长（P17）**
项目立项 → 报名与出勤 → 时长申报与审核 → 志愿者星级认证 → 申诉，5 张 `volunteer_*` 表、26 条路由。平台**不做认定与自动授予**：星级只按《志愿服务管理办法》第三十条的 50/100/150/300/500 小时档位推算展示，认证权属校青志中心；补录 6 个月与申诉 5 个工作日硬校验；黑名单 6 个月；信用时长与荣誉时数分开计。

**16. 校园文化：学生社团年审与星级评定（P17）**
5 张 `club_*` 表、22 条路由。年审结论只有合格/不合格/注销三档、星级只由 admin 登记，与志愿者星级**两套制度不得套用**；`attach_unit` / `business_unit` 不互换。审核权映射 `admin`，辅导员只录入/提报。

**17. 宿舍智能分配与可解释决策支持（核心算法模块）**
（a）分配：块分解 → 贪心构造 → 带桶守卫的局部搜索 → 阻塞对修复；五类硬约束（性别、楼栋、年级、特殊房型、容量）在全部实验中 100% 可行、无一人未分配〔docs/结题材料/结题报告.md:20；docs/实验与验证.md:75〕，n=10000 规模仍可在秒级完成〔docs/结题材料/结题报告.md:32〕。

## 五、技术特点

### 5.1 可解释分配：解释链

系统不把「分数高」当作可交付结论，而是把决策依据拆成管理员能复述的四层：命中的硬约束 → 相容度分解到具体特征与权重 → 志愿满足情况 → 与「别人怎么住」的对比〔docs/结题材料/结题报告.md:24-25〕。理由来自对现实的判断：宿管手工微调的可解释性是它唯一也是决定性的优势，自动化方案必须先在这件事上至少持平〔同上:95〕。

### 5.2 隐真值评估：用「看得见的偏差」代替「好看的数字」

实验用合成数据生成**隐真值** `g`（含算法看不见的磁铁效应项、睡眠交互项与 `ambition` 权重 0.12），所有质量指标都在 `g` 上计算，而不是在模型自己的目标函数上算〔docs/实验与验证.md:19-26、330〕。同一套口径还用来给启发式解「打分」：用 CP-SAT 精确求解器当裁判，n=200 时 5/5 证明最优、平均间隙 **2.54%**〔同上:270、290〕。这条纪律还促成了一次自我纠错——原模型用均值补齐缺失特征，等价于把「没回答」算成「很合得来」，修正后绝对表现下降 3~4 个百分点〔同上:127-149、414〕。

### 5.3 缺失感知补采（MAA）：把「没回答」当成一等公民

- **语义**：`c_ij = Σ_d w_d · c̃_d(i,j)`，`c̃_d` 仅在双方第 d 维都已知时取相容度，否则取 0（中性），实现于 `RuleBasedCompatibility.java:24-33`（刻意删掉了 `imputed(mean)` 分支）〔docs/创新点-不确定感知的宿舍分配.md:26-42〕。
- **可评估性门限**：`Cov`（同房对双方都已知的维度权重均值）与 `Eval`（至少一维可比的同房对占比）；建议 `Cov < 0.15` 或 `Eval < 0.5` 时不得把分数当结论〔同上:54-56、154〕。实测缺失率 0 → 0.25 → 0.50 → 0.75 时 Cov 为 1.000 → 0.481 → 0.200 → 0.056，MAE 为 0.0985 → 0.3556 → 0.5105 → 0.5979〔同上:147-154〕。
- **信息价值排序**：每格补采的期望增益 `Δ_{i,d}` 用于排「先问谁、问哪题」，10% 预算下 `voi − random` 为 **+0.0039 ± 0.0074**（8/10 种子为正）〔同上:169-171、188〕。
- **产品化**：管理端第 8 个 tab「补采建议」，两个只读接口 `GET /api/dorm/missingness/summary?batchId=` 与 `GET /api/dorm/missingness/priority?limit=`，受 `DormStaffInterceptor` 保护（默认仅 admin），**不读隐真值表、不写表**〔同上:210-227〕。线上实测（1000 名学生 / 1469 个同房对）：全员答齐时 `cov=1.0`；333 人三题置空时 `cov=0.6814`；800 人 11 题全空时 `cov=0.0209`、`evalRatio=0.0395`、`pairsWithoutEvidence=1411/1469`、`evaluable=false`〔同上:221-225〕。

### 5.4 离线内网与零运行时依赖

### 5.5 可审计与可复现

## 七、软件说明书（正文）

NEST 是一套面向高校学生工作与后勤部门的宿舍智能分配与可解释决策支持系统，同时承载请假、奖惩资助、勤工助学、困难认定、综合素质测评、评奖评优、心理健康、社区管理、学生党建、志愿服务与社团管理等学生工作业务，共 46 个页面。系统以 Java 17（Spring Boot + MyBatis）为后端，MySQL 存储数据，前端为静态多页面并预编译样式，全部资源本地化，可在完全离线的校园内网运行，也可安装到手机主屏使用。

系统的核心能力是把宿舍分配形式化为带硬约束与多目标软项的分组问题，并通过「块分解—贪心构造—局部搜索—阻塞对修复」求解；分配结果可解释、可审计、可被反事实提问：管理员能看到每条约束的命中情况与相容度分解，学生提出换室友诉求时系统会试算并报出代价。系统还把问卷缺失当作一等公民：未作答维度按中性处理而非均值插补，并给出证据覆盖率、可评估门限与「先问谁、问哪题」的补采优先级，避免在没有证据时把分数当结论。

全部功能均以真机端到端脚本与单元测试验收，当前单元测试 1458 项全部通过，主实验在 36 组配置、10 个种子上完成 1440 次求解，并配有可复现命令与部署文档。

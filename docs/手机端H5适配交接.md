## 2. 手机端方向（本任务的定义）

- **H5 网页 + 响应式适配**：同一套 48 页 HTML，用 CSS 断点 + 少量 JS 适配手机宽度（375px → 768px → 1024px → 1440px）。
- **不做原生小程序**。理由：平台已具备 PWA（可「添加到主屏幕」）+ 响应式基础，H5 一套代码通吃 PC / 手机浏览器 / 微信内置浏览器。
- **微信小程序 = 可选后续**：如学校坚持要「微信小程序」入口，走 WebView 壳方案（小程序里嵌一个 H5 页面），不需要重写业务。见 §10。

## 3. 后端 API 全貌（手机端要调的就是这些）

### 3.1 通用约定

- 每个接口都返回 **HTTP 200** + JSON：`{ "code": 200, "message": "…", "data": … }`。
  - 成功：`Result.success(data)` → `code=200`。
  - 业务失败：`Result.error(msg)` → `code=400`（部分权限/未登录为 401/403，但 HTTP 状态码仍可能是 200）。
- 认证用 **Session + Cookie**（`JSESSIONID`），不是 JWT/Token。
  - 登录成功后后端只在 Session 里存 **`userId` + `role`** 两个最小字段（见 `AuthController.java:41-48`）。
  - 前端请求时浏览器自动带 `JSESSIONID` cookie，无需手动塞 header。

### 3.2 认证接口（`AuthController` → `/api/auth`）

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/auth/login` | 登录，body `{username,password}`；成功后 Session 存 `userId`+`role` |
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/logout` | 登出（`session.invalidate()`） |
| GET | `/api/auth/me` | 取当前登录用户（按 Session 里的 userId 查最新） |
| POST | `/api/auth/send-code` | 发重置密码验证码（真生成 + HMAC 入库 + 5 分钟过期 + 一次性 + 限流） |
| POST | `/api/auth/reset-password` | 重置密码（真校验验证码） |

## 8. 关键坑（踩过的，别再踩）

1. **PowerShell 是 5.1**，不是 7：跑脚本用 `& .\target\x.ps1`（不是 `pwsh`）；`.ps1` 脚本必须纯 ASCII（5.1 读无 BOM 的 .ps1 当 ANSI，中文注释会乱码 + 解析失败）。
2. **中文 `.mjs` 用 write/edit 工具写**，别用 `Set-Content`（`-Encoding ASCII` 会毁中文，`-Encoding UTF8` 会加 BOM）。
3. **daisyUI 锁 4.12.24**，Tailwind 锁 3.4.17，别升级。
4. **加任何响应式类（`md:`/`lg:` 等）必须重跑 `build-web-assets.ps1`**，否则 `nest.css` 里没有对应规则，门禁会挂。
5. **窄屏横向溢出的元凶在页头 `navbar-end`**：修法是用 `hidden md:flex` 包一层隐藏，**不要**用 `overflow-x:hidden` 全局糊（会遮住真正的溢出问题）。
6. **触控目标 ≥44px 只能写在 `@media (max-width:1023px)`**：因为 `check-unify` 在 1440px 宽断言 `.nx-btn` 高 32/40/46px，全局改会挂。
7. **超宽表格**用 `<div class="overflow-x-auto">` 包起来左右滑，别缩列。
8. **遮罩弹窗**要 `.classList.add('flex')` 才会居中显示。
9. **`verify-css.ps1` 会把 JS 字符串字面量误判成 class**，别慌，看是不是真 class。
10. **下拉框文字发虚/被裁**（已修）：见 §6.6，新增 select 不要覆写这个修复。
11. **登录用 Session**：一次新登录会让上一个会话失效；后端重启会清空所有 Session。
12. **手机宽度验证必须真机或 headless 指定视口**：`check-unify` 默认 1440，`check-redesign` 默认 1440；测手机要用 375/768 视口的 `mobile-audit` 脚本。

## 10. 微信小程序衔接（可选，学校坚持才做）

学校若坚持「微信小程序」入口，推荐 **WebView 壳**，不重写业务：

1. 用小程序开发者工具建一个壳，放一个 `<web-view>` 指向平台域名（需 HTTPS + 已在微信后台配「业务域名」）。
2. H5 端已具备 Session 登录，WebView 内直接可用（微信内置浏览器走同一套 cookie）。
3. 需要学校侧提供：**小程序 AppID**、**已备案域名 + HTTPS 证书**、**业务域名配置权限**。

> 备注：当前平台**没有微信登录（openid）打通**，也没有短信网关。若小程序要「微信一键登录」或「短信验证码」，属于新增后端能力，不在本交接范围，需要单独排期。
